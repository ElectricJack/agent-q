# F7 aqv2 Human CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship the `aqv2` human CLI over the dashboard's existing domain reads and action union.

**Architecture:** A small standalone workspace crate uses `aq-human-http` for bounded, authenticated, same-origin HTTP without retries. Command translation consumes the pinned dashboard-action fixtures; the server remains the sole authorization and domain owner. Unavailable domain operations refuse explicitly, and uncertain submissions retain the minted operation ID for read-only recovery.

**Tech Stack:** Rust 2024, clap, tokio, serde_json, uuid, existing aq-human-http.

**Spec:** F7 contract in `2026-11-02-v2-full-application-tasks.yaml`; existing action contracts and fixtures in `protocol/dashboard-actions/v1/`; human conversation contract in `protocol/human-supervisor-conversation/v1/`.

## Global Constraints

- Rust uses the committed lockfile with `--locked`; no sibling dependencies.
- Binary name is `aqv2`, never `aq` or `agent-queue` while v1 is live.
- Mutations use only `POST /api/v1/actions`; recovery uses only `GET /api/v1/operations/{id}`.
- Do not define new action kinds, implement supervisor runtime or onboarding, or edit canonical architecture/spec documents.
- Server decides authorization; client authentication uses `--origin` and `--cf-access-token-file`, existing private-file checks and `X-AQ-Request: 1`.
- No automatic mutation retry, including after ambiguous transport/response failure.
- Focused and area checks follow AQ resource controls. Record exact commands, environment, commits and limitations in `docs/implementation/F7.md`.
- Preserve and publish the assigned task branch using guarded AQ commands; integration owns delivery.

## Review Focus

- Lost mutation response: exactly one POST, visible operation ID, GET recovery with the same ID.
- Conflict/rejected/pending/unknown responses: nonzero exit, stable JSON, no success claim.
- Unsupported cancel/retry/enrollment/revocation/onboarding: explicit `unsupported`, no alternate route or effect.
- Chat history containing the user's own text, old messages or no runtime: never print these as a supervisor reply; deadline returns nonzero.
- Untrusted origins, credentials, paths and response bodies: reuse bounded human HTTP, suppress raw error bodies, escape control characters in terminal output.
