# Enqueue Work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Owners and scoped supervisors create tasks and atomic dependency graphs through retained operation receipts.

**Architecture:** Extend the existing owner `task.create` payload compatibly with optional enqueue metadata. Add `task.graph.create` using the existing typed Graph action journal. A supervisor registry exposes only these creation kinds, authenticates F1b's generation-bound `enqueue` credential and journals against its session identity, independently of Owner accounts.

**Tech Stack:** Rust, Axum, SQLx/PostgreSQL, aq-graph API v1, generated JSON Schema.

**Spec:** AQ task steady-harbor-87.3; F2 in `2026-11-02-v2-full-application-tasks.yaml`.

## Global Constraints

- Rust uses the committed lockfile with `--locked`.
- aq-graph owns task state; AQ owns grants, attempts and dispositions.
- A wire change publishes schemas and fixtures from the contract owner.
- Named tests must exist and pass; evidence is `docs/implementation/F2.md`.
- Use focused tests under AQ resource admission, per owner velocity rules; CI owns unrelated full-suite coverage.
- Integration owns delivery to main; push the assigned leaf branch.

## Review Focus

- Changed operation bytes conflict without a second effect.
- Missing, reduced, revoked or expired supervisor credentials cannot enqueue or look up receipts.
- Cross-project references fail before dispatch.
- A lost response replays the retained exact Graph body/key after restart.
- Graph's 100-operation bound counts nodes and edges, including parent edges.

### Task 1: Typed creation payloads and atomic graph creation

**Files:** modify `crates/aq-server/src/agent_access/human/commands.rs`; create `human/enqueue.rs`; modify `human/graph_actions.rs` and action registry; test `tests/dashboard_task_knowledge.rs`.

**Interfaces:** consumes `GraphPayload`, `GraphAction<P>`, `Current` and existing native task-create journal. Produces `task.graph.create` with project, expected project revision, task nodes and blocks edges; optional task fields `priority` (1–300), `profile_hint`, `intelligence_hint`, `task_type` stored under `aq:` metadata keys. Explicit UUID node and edge IDs make retries stable.

- [x] Extend owner Create with optional metadata; preserve omitted-field serialization for native compatibility.
- [x] Implement typed GraphCreate validation: 1–100 total mutations, unique nonnil IDs, no self/duplicate blocks edges, at least one new endpoint per edge, parent validation, scoped existing task references.

### Task 2: Scoped supervisor creation
