# B3 — Native cancellation

The owner cancellation endpoint dispatches native attempts through
`profiled_execution::cancellation::cancel`. Immutable operation receipts retain
the cancellation identity and reason. Exact replay returns the original receipt;
a changed attempt or reason conflicts. Node → attempt/hot locks serialize this
owner with grant and result owners. Cancellation after an accepted evaluation
returns `already_accepted` and preserves that evaluation.

Schema 43 adds immutable cancellation, replay and cancelled-settlement rows.
Offered/preparing cancellation invokes the actual NeverGranted owner in the same
transaction, including typed preparation and absence-of-effects checks. It
releases the task claim without fabricating stopped evidence. Granted/started
cancellation fences further authority and agent credentials while retaining
task/source/effect claims. Cancelled settlement requires the actual stopped
owner's matching receipt and writer-stop proof; SQL checks its digest and binding.
Frozen and Refresh stopped paths share this hook. Late results remain readable
history and cannot apply successful completion after cancellation.

Poll authenticates the current node credential and exact admitted boot, then
reads cancellation before scheduling capacity/configuration/inventory. Zero-slot
polls still receive the existing `OwnerRequest` directive. Renewal verifies the
full binding and owners before returning the existing `FailureCode::Cancelled`.
When cancellations are pending and scheduling capacity is available, poll waits
at most 750 ms for offer assembly. The assembler continues after that response
wait; a semaphore bounds concurrent assemblies throughout their lifetime. Heap allocation of the shared offer future avoids stack exhaustion
without changing test thread stacks or authority deadlines.

## Environment and scope

Validation uses disposable PostgreSQL databases on the local PostgreSQL 17
service at port 55432, synthetic qualified runtime/Graph/Git peers and fake
Started/stopped worker evidence. Tests exercise actual SQL/domain/HTTP owners.
They do not qualify physical stopping, worker observation, permit revocation,
automatic result settlement or production-load recognition latency. No wire
contract, worker permit implementation or D3 automatic settlement was added.

Cargo commands run through a temporary pytest wrapper under the foreground
`aq test` gate, with `CARGO_BUILD_JOBS=2`, `CARGO_INCREMENTAL=0`,
`CARGO_PROFILE_DEV_DEBUG=0`, `RUST_TEST_THREADS=2` and an isolated target directory
at `/tmp/aq-b3-slot2-target`. Broad fixture runs additionally use
`-- --test-threads=1`. Dependencies use the committed lockfile. Full CI remains
integration-owned; the assigned worktree is retained.

## Review and limits

Fresh whole-branch review covered implementation based on
`86ca27966346a84dba674eaec129956d84ec85c5`. It found an Important offer-starvation
issue: dropping scheduling after the 750 ms response wait prevented a replacement
from persisting after a slow Graph resumed. The controlled regression failed RED;
bounded continued assembly made all five cancellation tests GREEN. Follow-up
reviews approved that correction, the shared offer-future heap boundary and the
equivalent NeverGranted `let Some(phase)` lint correction, with no remaining
findings. B3 is not marked for a cross-family adversarial loop.

The existing paired-stop test expected schema 33 rejection messages despite
schema 38/39 already replacing those guards. Its two assertions now require the
current exact result-origin and release-owner rejection messages. Both rejection
checks and the unchanged-state assertion pass.

Broader suites are **not claimed green**. Serial `native_initial_grant` runs
varied from 40 passed / 1 failed / 13 ignored to 31 passed / 10 failed / 13 ignored.
Failures include expired preparation/selection or execution authority and a
quota-lock observation timeout. A legacy restoration case passed unchanged when
run alone. These results are consistent with short fixture deadlines under load,
but do not establish that every failure predates B3. Deadlines were not relaxed.
The ignored cases require explicitly pinned external Git/physical worker tools.
The latest `phase_terminal_stopped` run passed 3 tests; its remaining case failed
during preparation with `accepted preparation v2 is not currently available`.
It had passed in an earlier run. Logs are retained in the assigned worktree's
`.aq/tmp/b3-*.log` files.

Changed Rust files pass `rustfmt --edition 2024 --config skip_children=true
--check`; `git diff --check` passes. After component integration,
`cargo fmt -p aq-server --check` passes. `cargo fmt --all --check` still encounters
the nested vendor/worktree workspace-membership error for
`vendor/aq-lifecycle-protocol-0.1.0`. Earlier server-format import-order failures
were corrected upstream and are absent from the merged tree.

Before integration, `cargo clippy --locked --all-targets -- -D warnings` failed
