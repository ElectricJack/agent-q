## Field reconciliation

- Envelope: `api_version`, request ID, scope, server time, observation, coverage and pending operations retain dashboard-read-1 semantics. Source coverage and timestamps identify unavailable, sampled and observed data; unknown values are null, never inferred zero.
- Overview: counts describe ready, running, recovering and eligible decisions from their respective owners; bounded counts may be estimated. Attention has typed kind, subject reference, project, reason, impact, nullable `since` and nullable action. Missing decision transition time remains null and no mutation authorization is advertised. In-motion project rows report running count and available constraint/progress. Outcomes distinguish process failure from settlement evaluation acceptance. Questions and blocked tasks are explicitly unavailable; result, worker association and operation coverage is bounded. Source entries expose observation, coverage, project and total.
- References: decimal revisions remain numeric strings; only entity references also accept `sha256:` digests. Result and settlement pins are retained owner content digests. Worker MVCC pins identify observed rows; operation digest identifies immutable request intent, neither historical lifecycle authority. Readiness comes from the scheduling owner; running requires current attempt authority and observed process state.
- Search: five typed task/session/result/playbook/knowledge groups expose sanitized title/excerpt, project and pinned reference, `has_more` and opaque continuation. Snapshot, per-source coverage and totals describe bounded observation; unavailable/unrequested owners remain partial with null observations and unknown totals. Current authorization and binding are rechecked on delivery; replay preserves snapshot members, while expiry, restart or changed bindings refuse continuation.
- Provider usage: inventory is deduplicated and account scoped; window state, nullable used percentage, reset/observation times and coverage represent actual source observations. Unknown is not zero; stale retains last-success time. Project scope does not filter accounts.
