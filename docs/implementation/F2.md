# F2 — Owner and supervisor enqueue work

Task: `steady-harbor-87.3`. Contract owner: aq-server. Consumers: F7 CLI,
G3/G8 dashboard, F1b supervisor. This change supplies the API, not those clients.

## Behavior and authority

Owners use `POST /api/v1/actions` and `GET /api/v1/operations/{id}` on the human
listener with current Owner authorization. `task.create` preserves the migrated
G1b payload and native task-create recovery. Its optional creation metadata is
priority (1–300), profile_hint, intelligence_hint and task_type. These become
`aq:priority`, `aq:profile_hint`, `aq:intelligence_hint` and `aq:task_type`.
Omitted options preserve native serialization. Project selection is the project
subject; graph creation also pins the same project_id in its payload.

`task.graph.create` accepts explicit task IDs, optional parents, and explicit
blocks edge IDs/endpoints. Every edge includes a new endpoint; existing task
references must match the current project and Graph workspace. IDs must be
nonnil and unique; self/duplicate dependency edges are refused. Graph enforces
cycles and domain rules. All nodes, blocks edges and generated parent edges
count against **100 total mutations**, sent in one atomic Graph request.
A graph is never split into independently committing chunks.

The worker listener exposes the same action and lookup paths with F1b's
`enqueue` bearer scope. Only these two creation kinds are registered. It checks
active head generation, session, expiry, revocation and scope using F1b's
transactional authentication and holds lifecycle/credential locks through the
protected operation. Other machine credentials and human account credentials
confer no supervisor authority. The journal principal is the supervisor session
UUID, not an Owner account. Credential rotation in that session preserves
receipt access; a different generation/session does not inherit it.

State format 58 adds explicit owner/session journal references and a disjoint
principal constraint. Existing rows are backfilled as Owners, retaining their
user FK. Machine creation rows reference central session generations. Principal
binding is immutable. Task metadata records either the human actor or supervisor
actor/session without manufacturing execution, assignment or launch authority.
The migration temporarily disables the existing operation guard inside its
transaction for the Owner backfill, then restores it; retired tombstones retain
their full original identity and terminal data. Single-task parent references
are checked against project metadata both at admission and before dispatch.

The shared G1b journal commits operation ID, principal, scope and canonical
request digest before adapter execution. Identical terminal retries return the
retained operation; changed valid requests conflict without another effect.
The G2 Graph intent journal retains the exact body/key/service/project binding
before POST. A lost response remains unknown and reconciliation on lookup or
repeated submit replays the original bytes under
`aq-dashboard-action:{operation_id}`. Changed service or binding prevents replay.
Initial stale versions or Graph conflicts are terminal. New rejection after an
ambiguous effect cannot prove the original effect absent.

## Published contract

`protocol/dashboard-actions/v1/schema.json` is generated from the production
registry. Fixtures include legacy task.create without new options, creation with
metadata, graph creation with parent/dependency edges, graph replay, and invalid
priority/ID/batch cases. The fixture checker validates total operations and
relational constraints as well as JSON Schema. Native human task-create schema
and documentation include the same optional fields. Both read/action contract
version compatibility and current schema digest pins are checked.

## Validation

RED evidence was observed before implementation: owner graph returned 422
unknown_action_kind, owner single metadata returned 422 invalid_request, and
`supervisor_creates_graph_with_dependencies_idempotently` returned 404 before
the scoped route existed. Commands ran through AQ test resource admission using
a local pytest subprocess adapter. It uses CARGO_BUILD_JOBS=2,
RUST_TEST_THREADS=2, CARGO_INCREMENTAL=0 and the disposable PostgreSQL fixture on
127.0.0.1:55432. No provider or external service was called; the fake public Graph
API retains atomic idempotency receipts and compares replay bytes exactly.
Timeout tests advance Tokio virtual time rather than waiting in real time.

A fresh whole-branch review found two Important defects: the principal backfill
initially hit the immutable retired-row guard, and Owner single-task creation
did not reject a parent from another project. Both received failing regression
tests before fixes. There were no Critical or Minor findings.

## Completion decisions

- Execution proceeded inline under the held task's explicit completion and
  publication instructions; the concrete branch received a fresh final review.
- Machine actions use the canonical API paths on the worker listener because
  F1b credentials have independent authentication. Clients must select that
  listener; the typed action and receipt contracts remain shared.
- Scheduling, existing-task edits, supervisor dispatch/reply and CLI/dashboard
  implementation retain their B4/G2/F1b/F7/G3/G8 ownership. F2 publishes their
  creation contract; priority scheduling already consumes the metadata.
- The feature was squashed to `4f96aae5` from base `3fea57fb` without changing
  its tree, then merged with origin/main at `4cf2121e`. Main's migration 57 was
  preserved and the enqueue principal migration and state-format pins moved to
  58. The merged tree passed the final checks above before guarded publication.
