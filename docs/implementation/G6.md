A Result uses the first report in its supersession chain as stable identity.
Report IDs remain compatibility aliases for exact revision lookup. Migration 44
adds immutable policy snapshots, comment revisions, feedback origins and effect
receipts. The retained report owner snapshots task policy inside its insertion
transaction before publishing the report head. Historical reports backfill an
explicit empty policy revision 0. The settlement39 native catalog stays intact;
no supplemental trigger modifies its exact trigger set. State format 44 is
registered in the server and Docker build metadata.

Task policy is stored in append-only `result_task_policies`, keyed by project,
task and policy revision. SQL validates bounded PNG requirements, all required
fields, unique requirement identities and matching policy revisions. Each report
pins a copy. Policy authoring and completion-policy integration remain with their
owners. Evaluation counts only finalized, retained, not withheld media bound to
that report/digest with matching declared scenario/environment/viewport/source,
or an Owner waiver of the exact requirement/policy. Human capture metadata is a
claim, never proof that the steps ran or that work is accepted. Assessment
versions advance separately as feedback/evidence observations change, including
retention expiry. Acceptance stays explicitly `unreviewed` in this projection.

Immutable revision fields describe native submitted content. Native reports have
no supplemental media, check-list or addressed-feedback fields; those submitted
arrays are empty. Later PNG attachments appear in the mutable assessment. A
waiver, upload, expiry or comment does not rewrite the revision. Open feedback and
applicable pending reviews or unsatisfied required evidence drive Needs review.
Following combines explicit result follows and opted-in threads across revisions.

Feed cursors use G1 authenticated bindings for principal, full identity, filters,
resource and page size. Result membership snapshots expire after five minutes;
comments freeze a SQL sequence ceiling. Default page 20, maximum 100. At most 128
live feed snapshots and eight readers per router; queries over 1000 eligible
results must narrow their filters. Each comment permits 16 retained revisions;
body bounds use UTF-8 bytes. Image regions require positive normalized bounds
and a retained exact-revision input/render digest. Video anchors receive typed 422
`unsupported_media_kind`; no duration/transcoding authority is fabricated.

Feedback drafts retain exact result/artifact/thread/comment-revision origins
before native dispatch. They reuse G1b `task.create`: task UUID and upstream key
are fixed by `operation_id`. Optional parent links are part of that same Graph
mutation. If linking fails after native creation, the G6 status route names the
task and its proven creation disposition independently of link confirmation.
Common operation lookup repairs the local link from the native receipt. Explicit
recovery also handles an interrupted intent before native admission and reuses
the original key. Read-only lookup never dispatches a Graph mutation.

The complete route and payload contract is in
`protocol/results-feedback/v1/README.md`; generated schemas and valid, invalid,
replay and compatibility fixtures accompany it. The common G1 action schema
includes all seven adapters and the optional native parent reference. Bootstrap
advertises `results.comment` and `results.feedback` only for the mounted Owner.

## Production storage handoff

The existing production runtime already reads `[result_media]`, opens the PNG
owner, performs initial cleanup and mounts it. `vault.example/config.toml` now
includes the opt-in settings. Installation configuration should contain:

```toml
[result_media]
root = "/var/lib/aq/result-media"
storage_id = "<one UUID generated once for this installation>"
uploads_enabled = true
```

E1a owns the production Compose change: mount a persistent private volume at
`/var/lib/aq/result-media`, provision it for the server UID with mode 0700, preserve
its installation storage UUID/root sentinel, and back it up with retained SQL
state. Do not replace the UUID or root on restart. G6 changes no production
Compose file and performs no deployment. The owner retains its existing PNG
bounds, quota/retention, private byte serving and cleanup behavior.

Without a configured store, bootstrap upload capability is false with
`Result media store is not configured`; admission/content/finalize routes return
typed 503 `media_store_unconfigured`. A configured read-only store keeps read
routes and returns 503 `media_upload_disabled` for writes. Shared current-Owner,
CSRF, maintenance and admission protections remain active.
