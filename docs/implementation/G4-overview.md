# G4 overview aggregation slice

Owner-backed `/api/v1/overview` replaces the empty placeholders. This slice follows quota and precedes search/final integration. It does not qualify a provider execution, physical worker, live Graph service, Git transfer, or a deployed dashboard consumer.

The response includes typed attention/outcomes, per-source observations and exact/estimated/unknown totals. Sources are bounded to eight configured projects, 100 attempts/journal operations, 32 ready tasks per project, 25 review/result records per project and 25 settlement evaluations. Source calls have a 650 ms budget under the route's existing two-second/four-request limit. Dashboard SQL retains its dedicated two-connection pool and local 500 ms statement/250 ms lock limits; existing owner APIs retain their own SQL controls. Source failure produces unknown/null contributions. Final principal and project binding fences run after owner awaits; source observations must remain fresh at delivery.

Readiness uses the scheduling-ready owner, never Graph active/completed lifecycle state. Running requires current common attempt authority plus an observed running process; unknown process-start state remains unknown. Recovery uses held cancelling/unknown attempts or stopped attempts whose source retention remains pending/unknown. Review reads use the encrypted owner inbox and its requester/eligible-owner visibility. `needs_you` counts the observed eligible code-review decisions and is estimated for sampled inbox reads; it is not an inventory of unmounted questions. Questions and blocked-task projections remain explicitly unknown because no suitable owner is mounted. Review attention has `since: null`: the existing owner has no decision transition timestamp, and expiry/result times do not substitute for it. Actions stay null because these reads do not advertise owner authorization to mutate.

Results use the full-principal native metadata owner. `process_failed` is a process observation. `settlement_accepted` is a retained evaluation, not confirmed Graph task completion. The result page is bounded UUID discovery, sorted by observed outcome time within the sample; it is not a globally complete latest-results feed. Settlement reads use the evaluation owner and retain its receipt digest. Native graph operations outside the dashboard journal are an explicit source limitation. Worker status uses the existing worker status function and configured offline threshold; project association comes from retained authorized attempts and is labeled partial.

`ReferenceRevision` widens only EntityRef/TitledRef pins to decimal Revision or SHA-256 Digest strings. Other numeric Revision fields remain decimal. Results use the exact retained report digest. Settlement evaluation pins use their own operation identity and verified receipt digest. Operation pins identify the immutable request intent, not disposition versions. Worker pins are actual PostgreSQL row MVCC versions read with the worker observation, not lifecycle revisions or a promise of historical worker lookup. Worker attention has no action.

Validation uses `aq test` resource admission and `.aq/tmp/g4/test_cargo.py`. The wrapper sets `CARGO_BUILD_JOBS=2`, `RUST_TEST_THREADS=2`, and `DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/postgres` against disposable PostgreSQL databases.
