# Distributed execution review

Reviewed 2026-10-30 against the shared [execution/recovery contract](../architecture/0002-execution-and-recovery.md), daemon specification and worker protocol contract. Scope: daemon execution authority/API/migration/tests and worker journal/runtime/driver/fixture/protocol. This is a source and regression review of the artifact-free, one-process synthetic adapter. Test results cited below were run and reported by implementation owners; the reviewer did not rerun the broad component suites.

The following blocking findings are resolved in the reviewed implementation. This does not accept the full recovery gate.

| Finding | Resolution and regression evidence |
| --- | --- |
| R1: New-boot registration blocked recovery of stopped pending reports. | The driver reconciles and retries immutable stopped reports before registration. Released reports retire only after acknowledgement. Unsafe prior writers/reservations remain held. `stopped_report_recovers_before_new_boot_registration_without_relaunch` passes. Server recovery permits bind the exact proposed boot, scan all centrally held writers, and recheck stop proof under the node lock before registration; omission and a new acceptance racing replacement are tested. |
| R2: Synchronous child waiting prevented cancellation and expiry enforcement. | The synthetic driver uses bounded asynchronous poll/renew waits, checks suspend-aware expiry, kills its owned child on cancellation/expiry/control failure, and reaps it before recording confirmed stop. Held-child cancellation and renewal-outage/expiry tests pass. A successful owned `Child` wait proves only this adapter's single process. |
| R3: Distinct cancellation IDs grew directive history without bound. | The daemon coalesces repeated cancellation requests into one worker directive while retaining operation receipts. Worker receipt admission refuses more than 64 distinct directives per attempt and preserves identical replays; the journal enforces a 32 MiB retained-state bound before writing and before startup deserialization. Coordinator coalescing and worker bound/replay regressions cover these paths. |
| R4: The fake coordinator accepted reports without valid binding/authority and released pending effects. | Protocol 0.1.1's fake peer requires an issued grant and matching boot/session/generation/spec, retains expired/replaced results as stale, and refuses retention release with unresolved operation IDs. Negative vectors cover these cases and nil/duplicate recovery identities. The protocol suite passes 10 tests; it remains a fake peer rather than production-storage evidence. |
| R5: Corrections overwrote the original immutable report body. | `execution_reports` stores each typed request and original disposition in the same transaction as its receipt/projection. Corrections update only the current attempt projection. `corrected_reports_preserve_original_immutable_body_and_admission` checks both bodies after reconnect, original replay and changed-byte refusal. |
| R6: Cancelling a never-accepted offer queued a directive for an attempt the worker had never journaled. | Cancellation now retires that offer without a process directive; node locking fences a racing acceptance. `cancelled_unaccepted_offer_never_queues_an_unknown_process_directive` covers the server boundary. The equivalent exact-image, real-worker scenario passed in the [connector integration qualification](connector-integration.md). |

Further review confirmed node-then-attempt locking plus the unresolved-task uniqueness constraint serialize conflicting assignments and cancellation/result admission. Acceptance and renewal replay return remaining time against the original stored expiry. Reconciliation grants no implicit lease extension; fresh renewal after confirmed stop is refused, with a regression added. Old-incarnation reports cannot settle newer authority. Worker implementation owners report four passing driver tests, including actual held children and restart recovery; passing runtime and protocol tests supply narrower local evidence.

WRK-04 remains open: discovering surviving descendants across parent death, closing the spawn/PID-record gap with a guardian or equivalent ownership mechanism, supported process-tree termination/escalation, safe reattachment and renewed authority require separate implementation and crash evidence. Current uncertain launches preserve reservations and refuse blind relaunch; that is not proof of descendant recovery. No provider harness, graph credentials, retained-source transport, task completion policy or production AQ host adapter is established by the synthetic fixture.

Scale, fairness, retention maintenance, separate control/graph/bulk request budgets, host-power-loss durability and the 500-agent product workload remain unqualified. Polling currently applies its SQL limit before resource-fit filtering, so earlier oversized offers can hide a later compatible offer until expiry; the one-assignment fixture must not be presented as fleet-placement acceptance. Journal quotas fail closed and require maintenance rather than proving indefinite service operation. No full recovery, capacity or production-readiness gate is accepted by this review.

## Packaging and integration review

The selected standalone worker source is commit `cf87edffa3384a08f5bb0319b4f92ffc2a26b145`, archive SHA-256 `6f54954b2ab38e9625fd5680fa70c63f512bf7e5ef74ec19d815e562fe176e15`. Review covered `check-worker-candidate.py`, `worker-command.py`, `product-smoke.py`, both Dockerfiles, lifecycle builds and CI/release wiring. No mandatory sibling source checkout remains: normal builds consume the verified vendored source archive and pinned public packages; `AQ_WORKER_BIN` is an explicit development override and official checks reject it.

Three packaging findings are resolved in the reviewed source:

- P1: Shared Cargo target caches could return stale binaries when changed archived sources had older timestamps. A disposable Cargo reproduction demonstrated this failure. Worker builds now key the target cache by the verified archive SHA-256; smoke, development, lifecycle and release builders supply that exact value. Daemon builds explicitly clean all local server/release/protocol packages before compilation, preserving registry dependency caches while preventing stale local libraries. Both Docker target-cache mounts also use `sharing=locked`, covering the complete clean/build/copy action so concurrent image builds cannot replace artifacts between compilation and copying. The development worker command uses a target-cache subdirectory keyed by archive SHA-256. Source revision labels alone are not treated as a cache invalidation guarantee.
- P2: Verification compared runtime contract sources but omitted published schema/conformance files. The checker now compares published fixtures, tests and other original package files against the selected source archive, with explicit exceptions for Cargo-generated files and a mapping from `Cargo.toml.orig` to the original manifest. It also checks source sets, versions, archive checksum, Git archive commit metadata and lockfile identity. The official checker passed. An independent negative test changed a copied public fixture and updated its declared hash; verification still rejected its disagreement with the selected source archive.
- P3: A timeout during log collection could prevent later teardown and evidence retention. Cleanup now attempts each action independently, falls back to removal restricted to the fixture's random Compose project label, confirms owned container/volume/network removal, and writes evidence in its finalization path. Independent fault injection confirmed that a log timeout still permits later teardown and evidence retention; an unavailable Docker path records unconfirmed cleanup, preserves the original failure and retains evidence.

Lifecycle builds select the standalone worker's revision/version/archive hash rather than substituting the daemon revision. Official release smoke requires digest-pinned images and compares embedded worker-candidate metadata with the selected candidate. Image smoke execution and final artifact acceptance remain owned by the integration evidence; this source review and its narrow negative tests do not substitute for those runs or close the recovery/capacity exclusions above.
