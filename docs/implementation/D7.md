## What shipped

### Contract

- `HOST7_COMMANDS` and `HOST7_CAPABILITIES` now include `candidate.prepare` (recovery `keyed_idempotent`) and `candidate.publish` (recovery `reconcilable`), as pinned in catalog 2.0.0.
- Both commands output `{reference, subject}`.
- Every settled result seals one `aq.integration.changed` event, `{outcome, reference, subject}`, in the same transaction as the final effect row and receipt.

### Storage (migration `0080_playbook_integration_receipts.sql`)

- `playbook_effects` now admits the two commands and the `prepared` and `published` statuses.
- New `playbook_integration_receipts` table: one row per candidate or publication operation, `UNIQUE(namespace, generation, intent_id)`. Each row holds:
  - the binding (repository id and generation);
  - a state: `pending`, `ambiguous`, `prepared`, `conflict`, `refused` or `published`;
  - a typed reason;
  - the request (the port call and verified evidence);
  - the detail (candidate OID, conflict paths, old/new or observed OID, reconciler op);
  - the reconcile attempt count (at most 64).
- DB checks enforce:
  - `settled_at_ms` is set exactly when the state is settled;
  - a prepare receipt is its own candidate operation.
- The intent (effect row with Intent.id, contract fingerprint and payload digest) and the `pending` receipt commit **before** the port is called.

### Port (`crates/aq-server/src/playbooks/host_adapters/integration.rs`)

`HostPorts.integration: Option<Arc<dyn Integration>>` is injected through `Service::new_host7_integration`. `new_host7` passes `None`. The port has five calls:

- `binding(workspace, project)`: repository binding plus `PublicationPolicy` and `EvidencePolicy {checks, review, judgment_choices}`.
- `prepare(PrepareCall)`: the operation id is the stable intent operation, which is also the candidate operation id.
- `publish(PublishCall)`: same operation id on every resend, used as D1's dispatch fence key.
- `reconcile(ReconcileCall)`: a fresh operation per attempt that targets the publication operation.
- `review(workspace, project, decision)`: the owning review service's record of a decision.

### References

| Item | Form |
| --- | --- |
| Base | `[<ref>@]sha1:<40 hex>`. D1 OIDs are sha1 only; anything else is `invalid_request`. |
| Sources | `aq.source/<uuid>`, 1..=64, unique |
| Candidate | reference and subject id `aq.candidate/<op>`, revision 1 (immutable) |
| Destination | `refs/heads/<branch>@sha1:<hex>` (target and expected old OID) |
| Publication | reference `aq.publication/<op>`; its subject is the candidate subject |
| Evidence | `check-receipt:<op>` (D6 check), `judgment:<op>` (D6 judgment), `aq.review.decision/<uuid>` (port) |

### candidate.prepare

- These refuse in a single phase: no port (`unavailable`), no binding (`policy_unavailable`), or a bad base or sources (`invalid_request`).
- Otherwise the adapter records the intent and calls `prepare`. A resume of a pending intent resends the same call.
- Replies map as follows:
  - `Prepared` → `prepared` (detail: candidate OID).
  - `Conflict` → `conflict`, reason `conflicted` (detail: step, at most 32 paths, truncated, count).
  - `Refused` → `refused` with a bounded token reason.
  - A port error leaves the intent pending (`Error::Unknown`).

### candidate.publish: guarded publication

Checks run in this order and refuse before the port is called:

1. `unavailable`
2. `candidate_unknown` (bad handle, or no prepare receipt in this namespace generation)
3. `policy_unavailable` (no binding, or a policy that names no evidence)
4. `candidate_stale` (revision ≠ 1)
5. `candidate_not_ready` (not `prepared`)
6. `binding_changed`
7. `invalid_request` (destination)
8. `destination_mismatch` (target ≠ policy target)
9. Evidence

Each evidence item is resolved in the store that owns it:

- **Check receipt.** It must be a D6 `check.request` row in this namespace (else `evidence_unknown`).
  - It must have run under `aq.check.sandbox/v1` (else `evidence_unauthorized`).
  - It must be bound to this candidate subject **and** the candidate OID (else `evidence_stale`).
  - Its status must be `passed` (`evidence_failed`, or `evidence_pending` while running).
- **Judgment.**
  - It must be a D6 `judgment.request` row (else `evidence_unknown`).
  - The policy must permit judgments, and the request's host-chosen credential profile must match the result's provenance (else `evidence_unauthorized`).
  - It must be bound to the candidate (else `evidence_stale`).
  - It must be `assessed` with a choice the policy allows (else `evidence_failed`).
- **Review decision.**
  - The port must know it (else `evidence_unknown`).
  - The issuer must hold review authority (else `evidence_unauthorized`).
  - It must be bound to the candidate (else `evidence_stale`).
  - It must be approved (else `evidence_failed`).
- **Caller-asserted ids** (anything else, such as `approved:true` or `check:passed`) are `evidence_unknown`.
- After every item resolves, every policy check, the review and the judgment must be covered (else `evidence_missing`). More than 64 items or duplicates are `invalid_request`.

Publish replies map as follows:

- `Published` or `ObservedPresent` → `published`.
- `Refused` with `target_moved` or `conflicted` → `conflict`.
- Any other `Refused` → `refused`.
- A lost reply or port error → receipt `ambiguous` and `Error::Unknown`.

### Recovery

- A settled intent returns its retained result with no port call.
- A resume of a still-`pending` publish resends the same operation id, and D1's dispatch fence answers it without pushing.
- An `ambiguous` publish is **never** published again. Each further dispatch reconciles under `stable_id(…reconcile, "<intent>#<attempt>")`:
  - `Present` → `published`;
  - `Resolved` → `refused` (`resolved_<disposition>`);
  - `Unresolved` → `Error::Unknown`, retried up to 64 attempts.

### Reads

- `operation.get` on a candidate or publication reference reports:
  - `running` while pending;
  - `indeterminate` while ambiguous;
  - otherwise `completed {outcome, output {disposition accepted|failed, reference, subject}}`.
- `Service::integration_receipt(reference)` returns the typed receipt for inspection.

## Production adapter (`crisp-meadow-36.8.1`)

- `DeliveryIntegration` (`src/playbooks/host_adapters/delivery_port.rs`) maps the port onto D1 without changing it:
  - `binding()` comes from the project's current D2 binding (it needs `publication`, `enabled`, and a matching project/workspace) plus the configured evidence policy.
  - `prepare` calls `create_candidate`, `publish` calls `deliver` and `reconcile` calls `operation_show` then `reconcile`.
  - `review()` reads the review-decision service as the namespace owner. The issuer is authorized only if the answering human is an eligible owner.
- The policy source is a new optional `[playbooks.integration]` section: `commit_name`, `commit_email`, `checks`, `review`, `judgment_choices`. It is only valid with the `host_v7` profile.
- Host7 startup binds the adapter only when that section is set. It refuses to start if the section is set but source retention (aq-git) is not configured. Without the section, Host7 still refuses `unavailable`.
- `AppState::delivery()` builds the `DeliveryService` from the source-retention config.
- The acceptance test is `host7_production_startup_prepares_and_publishes_through_delivery_service` in `tests/playbook_activation.rs`.
