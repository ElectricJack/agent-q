Both acceptance tests are in `crates/aq-server/tests/profiled_results/waits.rs`. They drive a real admitted review decision through `reviews::Service`.

What `wait_registration_replay_is_idempotent` asserts:
- A replay after the clock moves 5 s returns the identical response, with `original_created_at_ms` unchanged.
- The deadline stays at created + 30 days.
- The same `operation_id` with changed bytes returns `changed_payload`.
- A second active wait from the same attempt is refused.
- Exactly one `agent_waits` row exists.

What `wait_on_decision_wakes_once_after_resolution` asserts:
- The wait is pending until the decision resolves.
- Two reconciler passes give exactly one `satisfied` outcome and one `ready` resume intent.
- Inspect returns the same outcome.
- A stale continuation generation returns `stale_generation` and leaves the intent ready.
- A duplicate ack returns the identical receipt, and the intent is `consumed`.

## How each requirement is met

- **Migration 0082** (`crates/aq-server/migrations/0082_agent_waits.sql`; planned as 0076, renumbered to 0081 after main reached 0080, then to 0082 after H3 took 0081). Its tables:
  - `agent_waits`: one encoded `aq_wait_engine::Snapshot` per wait, plus the stored original response. It has `UNIQUE(caller_key, operation_id)` and a partial unique index giving one non-terminal wait per attempt.
  - `agent_wait_outcomes`: immutable.
  - `agent_wait_resume_intents`: states `ready`, `consumed` and `retired`.
  - `agent_wait_acks`: immutable.
- **Replay** (`waits::register`):
  - A registration replay is looked up by (caller principal, operation id) under `FOR UPDATE`.
  - `Snapshot::replay_registration` returns the stored response unchanged, so the age, deadline and budgets are never reset. Changed bytes map to `changed_payload`.
- **Credential and capabilities** (`waits/routes.rs`):
  - `POST /v1/agent/waits/{register,inspect,ack}` authenticate with the per-attempt machine credential.
  - Each route requires that the command capability equals `aq.lifecycle-api.wait`, `.inspect` or `.continuation-ack` respectively.
  - The caller's scope and binding are re-derived from authority on every call by `load_caller`, which uses `task_lineage_id` for the lineage.
- **Published contract.** `protocol/agent-waits/v1/{README.md, routes.json, fixtures.json}`. The request and response schemas are in `crates/aq-lifecycle-api/artifacts/`.
- **Unknown sources.** Any source kind other than Message, Task, Dependency and HumanDecision is refused with `unsupported_capability`.
- **Hold, re-observe, reconcile.**
  1. Register runs the engine's Install and Reobserve inside the locked registration transaction, for at most 4 rounds.
  2. If any member's hold cannot be installed, nothing is persisted and the caller gets `source_unavailable`.
  3. `waits::run` reconciles due waits every 5 s using `FOR UPDATE SKIP LOCKED`. Writes are compare-and-swap on the engine revision.
- **Atomic outcome.** The outcome and its `ready` resume intent are inserted in the same transaction as the snapshot update. Both inserts use `ON CONFLICT DO NOTHING`, so duplicate reconciliation is idempotent.
- **Ack.**
  - A duplicate `admission_id` with the same digest returns the stored receipt.
  - A different digest returns `changed_payload`.
  - A mismatched continuation id, generation, outcome or wait ref returns `stale_generation`, and the intent is not consumed.
- **Mail.**
  - Message waits read only the caller's task-addressed mailbox (`Recipient::Task`). They never consume a message, so a successor attempt still sees held mail.
  - Dependency waits observe graph task state only, so ordinary mail cannot satisfy them.
- **Bounds.**
  - 32 members and 30 days are enforced by the wire contract and the engine policy.
  - One active wait per attempt is enforced by a check plus the partial unique index.
  - Self-waits return `self_wait`.
  - A cycle across the task edges of active waits in the project (advisory-locked per project) returns `known_cycle`.
- **Owner routes for G10.**
  - `GET /api/waits[?project_id=]` and `GET /api/waits/{wait_id}` require owner auth.
  - Show returns the view, phase, revision, deadline, next due time, hold reason, per-member freshness and intent state.

## `source_unavailable` reporting

The engine does not let a temporary source failure become a terminal outcome:
- A temporary failure (`RetryableUnavailable`) keeps the wait pending.
- Its freshness is visible as per-member `MemberFreshness` and as the snapshot's hold reason, through inspect and owner show.
- `source_unavailable` as a refusal is returned only when registration cannot install the central hold.
