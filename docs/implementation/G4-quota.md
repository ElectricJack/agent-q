# G4 provider quota slice

The dashboard reads a deduplicated startup account inventory and exposes account-scoped quota to current owners. A project filter does not filter accounts. Configured accounts without an explicitly enabled source have unknown windows with null numeric fields. Config entries under `provider_quota` map `provider_id = "openai"` and a configured `account_ref` to a `chatgpt_account_id` and an absolute `auth_file` path; the mapping does not infer an account identity from a token profile. The file must be a regular, owner-only file owned by the server user. The collector neither refreshes nor logs credentials.

The qualified adapter reads only the fixed `https://chatgpt.com/backend-api/wham/usage` endpoint. It sends the protected OAuth access token and configured ChatGPT account ID, refuses redirects, bounds file and response sizes and time, caches account observations, and preserves last-success timestamps on faults. It maps the upstream percentages directly; it does not infer quota from tokens, cost, slots, or credential presence. Primary, secondary, and up to eight additional named rate-limit groups are distinct; absent windows are unknown. An oversized or malformed upstream response yields unknown or stale data. Only the OpenAI Codex ChatGPT account source is implemented; all other providers remain unknown. Synthetic loopback tests qualify the request and failure protocol only; no authenticated live-account drill or live credential inspection was performed.

Public source qualification is pinned to Codex commit `c60cda34a3ba6975f698d63da9e8ca8a1616f0c9`: [usage endpoint](https://github.com/openai/codex/blob/c60cda34a3ba6975f698d63da9e8ca8a1616f0c9/codex-rs/backend-client/src/client/rate_limit_resets.rs), [backend client authentication and mapping](https://github.com/openai/codex/blob/c60cda34a3ba6975f698d63da9e8ca8a1616f0c9/codex-rs/backend-client/src/client.rs), [usage payload](https://github.com/openai/codex/blob/c60cda34a3ba6975f698d63da9e8ca8a1616f0c9/codex-rs/codex-backend-openapi-models/src/models/rate_limit_status_payload.rs), and [additional windows](https://github.com/openai/codex/blob/c60cda34a3ba6975f698d63da9e8ca8a1616f0c9/codex-rs/codex-backend-openapi-models/src/models/additional_rate_limit_details.rs).

Synthetic contract examples are in `protocol/dashboard-read/v1/fixtures/provider-usage-*.json`; they are shape fixtures, not captured live account data. Test commands and exact results are recorded in the slice implementer report and `docs/implementation/evidence/G4/`. The controller owns the final integrated G4 evidence, consumer follow-up and publication.
