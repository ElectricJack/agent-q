### Adapters (`crates/aq-server/src/playbooks/host_adapters/requests.rs`)

Ports are injected through `HostPorts` via `Service::new_host7`:
- `CheckExecutor`: `pinned`, `start` (idempotent by operation id) and `observe`.
- `JudgmentProvider`: `credential_profile` returns a reference chosen by the host; `complete` makes one request with no tool loop.

**check.request**
- Accepts only an exact check id, the validator `ArtifactRef` and an immutable source OID (sha1 = 40 / sha256 = 64 lowercase hex), all validated against the 2.0.0 input schema. Undeclared fields such as `passed` or a shell command are rejected as `Invalid` before any adapter runs.
- The check must be in the pinned outcome's `required_checks` (≤32) with an identical validator pin, otherwise the request is refused `not_required`.
- A pinned revision mismatch is refused `stale_subject` with disposition `stale`.
- No executor bound → refused `unavailable`. Executions over the bound → refused `execution_limit`.
- Otherwise the intent is recorded, then one `CheckAttempt` is started under execution profile `aq.check.sandbox/v1`. The attempt carries no shell, URL or path. The command returns `accepted {handle}`.
- The receipt binds:
  - subject and check (id + validator digest);
  - source;
  - execution profile;
  - executor version;
  - inputs digest;
  - result artifacts;
  - exit/stop evidence, `exit {code, stop}`;
  - its own digest.
- Disposition mapping (outcome / disposition), all from executor-reported stops:

  | Executor stop | Outcome | Disposition |
  | --- | --- | --- |
  | Exit 0 with complete inputs | `passed` | `passed` |
  | Exit ≠0 with complete inputs | `failed` | `failed` |
  | Timed out | `infrastructure_failure` | `timed_out` |
  | Cancelled | `infrastructure_failure` | `cancelled` |
  | Missing input, signal, lost, or not found past the deadline | `infrastructure_failure` | `unknown` |
  | Revision mismatch | `refused` | `stale` |

  Missing input or an uncertain stop is never `passed`.

**judgment.request**
- Takes explicit context (text + artifact refs), a question, and an output schema (`choices`, `rationale_max_bytes`).
- Budgets: `max_input_tokens`, `max_output_tokens`, `max_cost_microunits` and `deadline_ms`. The provider deadline is `budget.deadline_ms` (≤600 s). It is not capped by the 60 s dispatch deadline, because the provider runs off the dispatch path (follow-up `crisp-meadow-36.7.3`).
- The host chooses the credential profile. If none is permitted → refused `no_permitted_profile`; the playbook is never asked for one.
- Refusals before any provider request: `invalid_request`, `stale_subject` (a graph node whose CAS version ≠ the requested revision) and `budget_exceeded` from the pre-call input-token estimate.
- Pre-call estimate: `JudgmentProvider::estimate_input_tokens` defaults to `estimate_input_tokens`, which is ⌈UTF-8 bytes of question + context text + choices ÷ 4⌉. A provider that inlines artifact contents should override it. An estimate over `max_input_tokens` is refused synchronously with null provenance. No operation is recorded and nothing is sent. The estimate is kept in the operation's `request` record as `estimated_input_tokens`.
- Asynchronous execution: once the intent commits, dispatch returns `accepted {handle}`. The provider request runs in a spawned task bounded by its budget deadline. That task completes the operation exactly once by the sealed `aq.judgment.completed` event.
- Results after the provider call (completed asynchronously):
  - Reported usage over any budget (the authoritative backstop to the estimate) → refused `budget_exceeded`. Usage provenance is recorded and `output_digest` is null; no choice is released.
  - Deadline → refused `deadline_exceeded`.
  - Answer outside the schema → refused `invalid_output`.
  - Provider error or unavailability → failed `provider_error` / `provider_unavailable`.
  - Otherwise `assessed {choice, rationale, provenance}`.
- Provenance: provider, model, credential profile **reference**, `prompt_digest`, `context_digest`, usage (tokens and cost) and `output_digest`. No secret appears.
- It produces only an `assessed` operation output. It never creates a human decision or check evidence.

**Completion and reconciliation**
- Each completion is sealed transactionally into `playbook_outbox` as a validated 2.0.0 event from `aq.host.bridge@1`, correlated by operation: `aq.check.receipted` or `aq.judgment.completed`. Its event id is stable per intent.
- `operation.get` reconciles the original operation:
  - completed → `completed {outcome, output}`;
  - running check → observes the same attempt;
  - running judgment past its deadline plus `JUDGMENT_RECONCILE_GRACE_MS` (5 s), so it does not race the in-process task → `failed` / `indeterminate`;
  - unknown handle → `refused`.
- A lost response re-dispatches the same intent and returns the retained handle. It never starts a second attempt or re-sends a provider request.
- `driver.rs` maps an `accepted` host result with a handle to `DispatchResult::Accepted`, on both dispatch and reconcile.
