## Result and contract reconciliation

- `tasks list/show/create/cancel/retry`, `decisions list/show/respond`,
  `messages inbox/send`, `chat`, `workers list/revoke/enroll`, and
  `projects list/show/onboard` are exposed. `operations show ID` provides
  explicit read-only recovery. The executable is named only `aqv2`.
- The three published action kinds (`task.create`, `decision.resolve`,
  `supervisor.message.send`) use exactly one `POST /api/v1/actions`.
  Each submission mints one UUID shared by envelope and payload; supervisor
  messages also mint a distinct message UUID. Decision files preserve the
  immutable subject binding and reject duplicate JSON fields recursively.
- `GET /api/v1/operations/{id}` recovers the original ID. Confirmed responses
  require a complete operation envelope, matching operation ID, expected
  API version, nonnil request UUID, and valid digest format. Pending, unknown,
  rejected, conflict, malformed response, transport loss and HTTP refusal
  produce nonzero errors. Mutation errors retain the original ID and recovery
  command. No retries, automatic recovery reads or legacy mutation fallbacks.
- Reads use existing domain owners: project enumeration uses `/api/v1/projects`;
  project inspection uses `/api/projects/{id}`; tasks use the human overview
  and project task routes; decisions use review routes; workers use `/api/workers`;
  conversation discovery/history use human conversation routes. Query values
  are URL encoded, pagination/coverage envelopes preserved, and project-qualified
  404 responses retain their neutral `not_found` meaning.
- Cancel/retry, worker mutations and onboarding have no published action kinds
  in the current registry. They return explicit `unsupported` without HTTP.
  Server `unknown_action_kind` also becomes `unsupported`, retaining the
  original operation ID and safe status/request metadata.
- Auth flags are `--origin` and `--cf-access-token-file`. The CLI reuses
  `aq-human-http` owner-only, nonsymlink JWT checks, HTTPS origin validation,
  bounded request/response/time limits, CSRF `X-AQ-Request: 1`, disabled redirects,
  disabled proxies and disabled retries. Domain authorization remains server-owned.
  A new opt-in bounded status/JSON transport API lets this CLI consume safe
  versioned error codes; existing typed GET/POST APIs retain their prior behavior.
- Global `--json` returns schema-version-1 success/error envelopes. Human
  output uses JSON escaping, including control characters. Untrusted raw HTTP
  error bodies and credentials are never reflected. Positional `--json` after
  `--` remains message text.

Implementation entry points: `crates/aqv2/src/cli.rs`, `actions.rs`, `client.rs`,
`chat.rs`, `wire.rs`, `json.rs`, `main.rs`; user examples and recovery details
are in `crates/aqv2/README.md`. Shared transport changes are in
`crates/aq-human-http/src/lib.rs`.

reviewer found single-submit recovery and shared transport protections sound.

not marked for cross-family adversarial AQ review.

The command/wire and recovery plan steps were implemented as one connected
RED/GREEN boundary because their observable behavior shares HTTP translation.
History combines the plan and implementation into one feature commit, followed
by an evidence-only commit recording the supervisor waiver. Published feature
history was not amended.

The published `human-supervisor-conversation-1` contract exposes human-only
history and explicitly unavailable runtime. `chat`, inbox and send use that
foundation. `chat --once TEXT --timeout N` discovers it and returns explicit
`unsupported` before sending. No reply fields, runtime semantics or substitute

qualification require F1b's reply/correlation contract and remain unqualified.

binding policy is not specified for this client. An authenticated server could
still provide an incorrectly bound, syntactically valid receipt. Full operation
envelopes remain available for inspection.
