# AQ-11 implementation evidence

The daemon now persists scoped task/session mail, immutable message and operation
identities, serialized mailbox cursors, agent receipts and exact-attempt node
handoff dispositions. Owner, agent and outbound node routes share existing
identity/current-authority controls. Explicit message capabilities are additive;
old API-01 fixture bytes and digests remain unchanged.

[Operations and limits](../operations/messaging.md) document the routes and
recovery semantics. [Evidence JSON](AQ-11.json) records exact file hashes,
commands, tests and logs. Source revision `8cbaba1729f48b10847cfe7aefc1cfcb10d63e46` is qualified for AQ-11; this is not a deployed artifact or completed product gate.

Before the narrow root-review revisions, 177 aq-server tests passed with disposable PostgreSQL; one existing
real aq-git qualification test retains its declared ignore. All 31 public contract
conformance tests, generated-file checks and warning-free server Clippy passed.
The final affected suite passes eleven messaging tests covering sender/recipient authorization, changed-payload replay,
concurrent cursors, durable reconnection, node delivery states, stale successor
exclusion, cancellation/revocation ordering, expiry while blocked, owner role/CSRF,
and bounded non-ASCII body retrieval.

Task mail can follow a successor only without prior unresolved delivery evidence.
A predecessor poll may already have caused an effect, so unresolved/unknown or
handed-off mail cannot be automatically injected into another attempt. Session
mail remains bound to its original attempt/session/generation. Oversized inbox
bodies produce explicit descriptors and UTF-8 chunk retrieval without silently
advancing the mailbox cursor. Node receipt/harness handoff and agent read receipts
remain separate facts.

Initial task recipients require a trusted provisioned launch binding. AQ-19 adds
pre-first-launch project/task targeting; AQ-17 adds central supervisor authority.
WRK-09/14 still own real harness injection/journaling. Unknown-delivery
reconciliation, retention policy, human notification transport and actual harness
qualification remain separate work. No production daemon/database, provider or
external notification was exercised.

Root-review revisions also require `message.read` for new node polls, independently
of graph-read capability. Exact existing delivery acknowledgements can report their
disposition without a new read grant while current attempt authority holds. Inbox
and body routes recheck expiry before returning content, with PostgreSQL relation-lock
wait tests proving expiration suppresses the response. Omitted-body descriptors now
include concrete `message_body` recovery and initial `body_request` fields. The final
review run passed eleven messaging tests, 31 contract tests, generator drift and
server format checks. The full server suite and Clippy results above predate these
narrow revisions; they were not rerun at root's request.
