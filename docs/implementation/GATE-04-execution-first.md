Priority decision, 2026-11-01: complete GATE-04 before extending suspend/wake,
additional harnesses or unrelated dashboard features. Existing independent work
and evidence remain retained; this changes delivery order, not acceptance rules.

## One acceptance scenario

An authorized task in a real aq-graph project is selected with its exact profile,
source base and outcome requirements. One worker prepares the workspace, launches
the first supported Codex harness in tmux, receives the actual task context and
can edit the worktree. Authorized terminal inspection shows its real output.
The worker records physical stop, retains the resulting source centrally and
submits an explicit result with check evidence. The required human/policy review
binds that result and revision. Central settlement records the expected-version
Graph completion through the existing mutation/reconciliation owner. A successful
process exit or agent conclusion alone does not complete the task.

The scenario must preserve source and recover the same operation after a lost
result or Graph reply. Cancellation, changed task revisions and unknown physical
state must retain their existing refusal/hold behavior.
