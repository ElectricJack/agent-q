# Native Prepare to initial grant

The candidate adds one machine-listener route and a separate atomic transition owner. It consumes the exact retained NativeOffer and PreparationPlan. The original Accept request is not retained and is never reconstructed to call acceptance helpers. Its retained digest is checked against the admitted material row; the preparation operation is resolved through the locked hot owner.

A first SERIALIZABLE transaction checks current authenticated credential/boot/runtime/policy, common exact authority, the original offer and actual linked artifact bytes/receipts, selected project/task/principal/registry facts, the preparation owner, admitted material row and complete claimed installation receipts. It commits before current Git retention inspection and bounded private-material fingerprint observation. A second transaction repeats the current fences and exact backing-byte checks, verifies the observed immutable source and material did not change, and samples time after awaited work.

The first grant writes HotGranted, a new immutable grant ID, immutable execution wall deadline, Prepared owner-journal head and immutable Prepare receipt in one transaction. Journal revision must advance beyond Reserved. A strict internal receipt retains the original grant versions and hard deadline alongside the existing `kind=grant`/`body` projection, so SQL never-granted contradiction guards continue to see issued authority. Public transport bytes are unchanged. The response adds a fresh delivery nonce/clock and the original immutable initial-grant versions around that original grant. Exact Prepare replay verifies the retained request digest and same current grant, rechecks current authorization and backing bytes, and returns the original grant/expiry; it performs no state mutation and cannot renew. A distinct operation cannot issue a second initial grant.

All original inline descriptors must be covered once, with at most 126 inline artifacts plus the two source members under the frozen 128-receipt wire limit. Source member identities are `aq.source-manifest/{transfer_id}@1` and `aq.source-bundle/{transfer_id}@1`, bound to the actual linked manifest/bundle digests and byte counts. Duplicate content digests or missing/extra receipts refuse. The current worker private binding profile uses `aq.private-material/{lease_id}@1`; its digest is the authenticated qualified runtime's opaque installation-record claim, not a daemon inspection of a remote filesystem. Actual private backing bytes and current admitted lease/configuration are checked by the daemon.

Initial expiry is bounded by the original preparation/material expiry, original offer/read-provenance and selection clocks, retained artifacts and the new execution wall deadline. No replay resets the hard deadline, original grant clock or initial expiry. Incoming and retained lease/response sizes both use exact PostgreSQL JSONB text bytes. The same retained-response byte quota and advisory lock cover Accept and Prepare; no eviction or quota expansion is introduced. Synchronous private reads run on a process-wide two-slot blocking lane and retain the permit if the outer timeout expires. Git inspection uses its existing bounded owner.

Only the exact already-granted replay case receives a separate resolver phase fence. Its own existing attempt is normalized when comparing the original decision, while retaining the canonical project/catalog/principal/registry/clock predicates; this is not permission to discount an arbitrary issued grant while admitting new work. The original never-granted preparation fence still refuses all issued grants.

Qualification must use an actually published offer from the assembler, not a fabricated replacement wrapper. Tests must cover exact replay, duplicate conflict, concurrent admission/replay, complete receipt coverage, source/private backing changes, credential/cancellation/expiry after waits, and atomic rollback of hot state/journal/receipt. No Started, renderer, model execution or optional owner activation follows from a grant. An issued grant without Started cannot use NeverGranted closure; qualified no-start recovery remains separate. Renewal/reconciliation are subsequent slices and are not provided by this candidate.

Receipt immutability in this slice means INSERT-only owning APIs plus exact request/body/current-owner validation. The existing table has no generic SQL UPDATE/DELETE guard. Same-privilege direct SQL/database administrators remain a trusted operator boundary; this candidate does not add a global history/retention migration.

Source ownership is explicit: the daemon rechecks current Git retention and the immutable export facts plus exact manifest/bundle receipt coverage. It does not perform an unbounded whole-bundle rehash during grant admission. The qualified downloader verifies whole transferred bytes before claiming installation; corruption of a central backing bundle may therefore cause fetch/preparation failure rather than guaranteed detection at the later grant recheck. No silent repair or replacement export is allowed. Inline artifact bodies and current private credential bytes are reverified during grant admission.

A crate-private historical reader returns the exact initial operation ID/request digest, original grant, original versions and hard deadline to subsequent Renew/Reconcile owners. It reads at most two candidates for the exact node/binding/grant and refuses ambiguity. It is not current execution authorization, and exposes neither a reconstructed Prepare nor private bytes.
