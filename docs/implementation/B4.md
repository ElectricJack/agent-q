## What changed

### Replacement (`crates/aq-server/src/profiled_execution/replacement.rs`)
- `assess` is pure. It takes a task's started (not never-granted) attempt history and server budget limits, and returns one of:
  - `Fresh`
  - `Replace(Replacement)`: the predecessor plus its stop, retained-source and effect-reconciliation receipts, with fresh `ReplacementEvidence` (TTL 2 s).
  - `Blocked(reason)`. Reasons:
    - `replacement_prior_execution_uncertain`
    - `replacement_effects_unreconciled`
    - `replacement_source_retention_unknown`
    - `task_already_settled_accepted`
    - `replacement_predecessor_not_failed`
    - `lineage_retry_budget_exhausted`
    - `lineage_time_budget_exhausted`
    - `task_sandbox_minutes_budget_exhausted`
- `precheck` (counts only) and `assess_task` (counts, then history load) are what the scheduler uses.
- `release` takes the node lock, then `FOR UPDATE OF a,h`. It re-assesses the locked history and checks the predecessor is unchanged. It then inserts an immutable `profiled_replacement_releases` row and sets `holds_task=false`.
  - This step is required: `execution_one_unsettled_task` admits only one holding attempt per task.

### Migration 0050 (`profiled_replacement_fairness.sql`; state format 49 → 50)
- `profiled_replacement_releases`: insert-only. Its trigger re-checks, from hot authority:
  - stop is `stopped`/`not_started`, retention is `retained`, effects are `quiescent`
  - all three receipt digests match
  - status is terminal or unknown
  - no accepted/stale/needs-reconciliation evaluation, and no task completion
- `profiled_historical_snapshot_guard` and `settlement_claim_guard` accept a replacement release as a lawful `holds_task` true→false. The change is one extra `NOT EXISTS`; everything else is byte-identical to 0015/0040.
- `profiled_project_schedule`: last service time per project.
- Startup attestation:
  - `store/replacement50.rs` checks the new guard function and trigger exactly.
  - `settlement39` and `never_granted40` compare the two replaced guard bodies against the 0050 text when the supported format is ≥ 50, and against the historical text before that.

### Resolver (`intelligence/resolver.rs`)
- `ResolveRequest.replacement: Option<ReplacementBudget>` (serde default; omitted when `None`).
- The request is refused unless `attempts_started` equals the server-counted started attempts, is > 0, and the evidence lineage equals the request lineage.
- When accepted, it fills `BudgetSnapshot.last_attempt_id` and `elapsed_ms` and `SelectionInputs.replacement`, so `aq-selection`'s existing budget fences apply.

### Fairness (`profiled_execution/producer/fairness.rs`)
- `order` sorts by effective priority = configured priority + seconds waited since last service. A never-served project counts as having waited `STARVATION_MS`.
- Any project waiting longer than `STARVATION_MS` (10 min) goes first, oldest first. Ties break on oldest service, then project id.
- `offers()` tries up to 4 projects per poll in that order. Each project's service is recorded before its Graph read, so a project with no work or a failing read cannot hold the head of the order.

### Named-ref sources (`producer/workflow.rs`)
- The two Immutable-only refusals are removed.
- The source is observed once, before the export operation is derived, and that observation is passed to `reservation`.
- `source_operation` keeps the historical 5-tuple key for Immutable policies. For NamedRef it appends the commit resolved at offer time, so a moved ref is a new operation and never a followed one.
- The existing second observation still refuses when the ref moved between the two observations.

## Limits

- Budget limits are server constants (`MAX_ATTEMPTS=3`, 24 h lineage, 240 sandbox-minutes). The selection policy's own `max_attempts` and `max_lineage_elapsed_ms` still fence. Per-project budget config is a follow-up.
- The sandbox-minutes charge is conservative: Σ(execution deadline − offer) per started attempt, not measured runtime.
- A successor takes a fresh source export; it does not reuse the predecessor's retained source. Successor-from-retained-source is a follow-up.
- Exhaustion is a scheduling block (the task is skipped and later tasks are still served). It is not a Graph-visible task state; owner retry and visibility belong to G2.
- Fairness is between projects only; task-level priority within a project is a follow-up.
- The replacement release path (`release`) has no end-to-end DB test with a real failed profiled attempt. Its trigger predicate and history SQL are exercised against the migrated schema, and the decision logic is covered purely.

## Proposed design-doc changes (not edited here)

- `docs/architecture/0002-execution-and-recovery.md`: document `profiled_replacement_releases` as the third lawful way to release a profiled task claim (after a verified Graph completion release and a never-granted closure), with its stop/retention/effects preconditions.
- `docs/specs/0002-execution-and-agent-access.md` (fair-share, §8.2): record the concrete algorithm. Priority plus 1 point per second waited; a never-served project starts at the starvation bound; a 10-minute hard starvation bound; at most 4 projects tried per poll; service is charged before the Graph read.
- `docs/specs/0003-project-execution-bindings.md`: NamedRef policies are admitted. The ref is resolved once at offer and its commit is frozen into the export operation key. A ref that moves before preparation refuses that offer, and the next poll freezes the new commit.
