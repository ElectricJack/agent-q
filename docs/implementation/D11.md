# D11: Routing, watcher and reporting pilots on real adapters (GATE-05 evidence)

Task `crisp-meadow-36.12`, plan key D11. The deliverable test is
`real_adapter_pilots_complete` in `crates/aq-server/tests/real_adapter_pilots.rs`:

```
cargo test --locked -p aq-server --test real_adapter_pilots   # 1 passed (~110 s debug build)
```

The test runs the three pilots and D9's coding policy. Each one goes
through the embedded host: the pinned runner, protected PostgreSQL engine
storage (`aq_playbook_host::protected::storage`) and `Driver::quantum`.
Effects reach the production Host7 adapters (`Service::host_dispatch`) on
disposable PostgreSQL.

## Twelve production commands

`HOST7_COMMANDS` and `HOST7_CAPABILITIES` now hold all twelve catalog commands.
The test asserts both of these:

- `HOST7_COMMANDS.len() == 12`, and the set equals the pinned registry's `commands` keys;
- the capability set equals the union of the registry's command capabilities.

Three commands were added:

- **`findings.reconcile`**: the D8 adapter, now enabled on Host7 (the 2.0.0 contract is byte-identical to 1.0.0). It comes with Host7 `context.read view=health_observations` and finding-notification flushing in the Host7 quantum. Schedules stay Monitoring6-only.
- **`message.send`** (`host_adapters/messages.rs`): a new Host7 catalog adapter.
  - The only granted recipient is `user:<namespace owner>` with visibility `project`.
  - The pending intent row carries the frozen `SendRequest` and commits before the notifications owner's `enqueue`. A failed or lost enqueue leaves the row pending, and recovery re-submits the same IDs.
  - The message id is derived from `identity`. A second message under the same identity with a different body is refused, so one report identity is sent at most once.
- **`decision.request`** (`host_adapters/requests.rs`): a new Host7 catalog adapter.
  - It records one running `playbook_host_operations` row and returns `accepted{handle}`.
  - `Service::answer_decision(actor, handle, choice)` is a trusted call, not a route. It accepts only a listed `user:<id>` responder and one of the offered choices (`approved` or `rejected`). It completes exactly once and seals `aq.decision.completed`.
  - `operation.get` expires the decision at `expires_at_ms`.
  - Migration `0089_playbook_host_decisions.sql` admits the `decision.request` command and its statuses on that table (see Migrations).

## Designated fakes, and the recorded extra fakes

The three designated fake peers:

- **Deterministic model provider:** a `JudgmentProvider` that always picks the last offered choice.
- **Fake notification destination:** a loopback Discord webhook behind the real notifications owner (routes, deliveries, dispatcher `tick`, retry policy).
- **Local bare Git remote:** a real `git init --bare` repository behind the D7 `Integration` port.
  - Candidates are the retained source commits. They are checked with `git merge-base --is-ancestor` against the base.
  - Publication is a compare-and-swap `git update-ref refs/heads/main <new> <old>`.

Everything else is real AQ code: `Service` and its adapters, the D6/D7 guards, the notifications owner, PostgreSQL and the pinned runner.

Extra fakes, recorded as limits:

1. **Graph:** an in-memory `WorkGraph`, because aq-graph is a separate service. The test plays the task lifecycle around it:
   - an implementation completes with `aq:source_receipt`;
   - a review completes with `aq:review_disposition=accepted`;
   - authoring completes when enabled.
2. **Sandbox check executor:** a `CheckExecutor` that exits 0, because production leaves the executor unbound (D6).
3. **Integration port:** the bare remote stands in for D1 `DeliveryService` plus aq-git. Production binds `DeliveryIntegration`, which `playbook_activation` covers.

## Pilots and their assertions

The test uses four fresh namespaces, one per group: coding with routing,
report, watcher, and decision with the base-change fault. This keeps engine
history bounded (see Limits, PB-04).

**Coding (D9 policy, unchanged).** The run goes: implementation work, then
`candidate.prepare` from the completed work, then the required check on the
candidate, then cross-family review work, then `candidate.publish`. The test
asserts:

- the outcome is `published`;
- there is exactly one `candidate.prepare` (`prepared`) and one `candidate.publish` (`published`);
- the bare remote's `main` equals the prepared candidate OID;
- exactly one check attempt ran.

Two D7 integration gaps blocked this flow on real adapters and are fixed here:

- `candidate.prepare` accepts a completed namespace work item as a source. The task's recorded `aq:source_receipt` resolves to the retained source receipt. Explicit `aq.source/<receipt>` sources still work.
- `candidate.publish` accepts `aq.playbook.work/<task>` review evidence. The review work operation must be completed with disposition `accepted`, and its ensure subject (`motivation`, now retained by `track_work`) must be the exact candidate.

**Routing** (`aq.pilot.routing`). The test asserts three cases:

- **Complete execution options** (a seeded `intelligence_attempt_selections` row): the outcome is `routed`, no `judgment.request` is made, and `aq:execution_constraints` is the observed selection digest.
- **Missing facts** (unknown attempt): exactly one `judgment.request` and one model call. The outcome is `routed`. The constraint names the retained judgment (`judgment:<op>`), whose AQ-held choice is the deterministic `isolated`.
- **Concurrent change between the work read and `work.change`**: the outcome is `stale`, and the constraints are unchanged.

The routing pilot only constrains the work item. Placement stays AQ-owned.

**Watcher** (`aq.pilot.watcher`). The host evaluator starts the scan, which
captures prior episode revisions, and then completes it. The run needs a
complete page-0 health read before `findings.reconcile`. The test asserts:

- **Open:** the outcome is `reconciled`, the episode is `(1, present)`, and there is 1 notification.
- **Stale baseline** (expected revision 0, episode at 1): `conflict`, and the episode stays open.
- **Incomplete scan with no findings:** `reconciled`, but it never clears.
- **Missing page** (`page=1`): `incomplete`, with zero `findings.reconcile` effects.
- **Reminder cadence parameter:** after 61 s, `reminder_ms=300000` adds no new notice and `reminder_ms=60000` adds one.
- **A complete scan without the finding** clears the episode, with one clear notice.

**Report** (`aq.pilot.report`). The test asserts three things:

- **Authored by the deadline:** the outcome is `authored`, with exactly one `message.send` (`queued`). The notification summary is the authored work reference.
- **Deadline:** the deterministic `REPORT_FALLBACK` is sent once. The run finishes only after its owned author operation settles.
- **Late author completion:** it is retained as a completed host operation. The `message.send` count stays 1 and the report message count stays 2. Exactly two `supervisor_authoring` items exist, one per run.

## GATE-05 fault cases

| Case | How | Asserted |
| --- | --- | --- |
| Crash between the domain effect and the runner receipt | `Driver::test_lose_next_host_reply("work.change")` (test-support only). The AQ effect and its final row commit and the reply is lost. Then `Driver::stop`, a new `Driver::start` over the same storage, and `recover()`. | The run is `routed`, there is exactly one graph mutation per idempotency key, and one `work.change` effect row (`changed`). |
| Lost effect response | The fake graph applies the mutation and drops the reply. The effect stays `pending`. Then `recover()`. | The resumed dispatch re-sends the same idempotency key. One application, and the run is `routed`. |
| Revoked authority | A second grant's report run waits for its author, then `Service::revoke` runs. | No authored or fallback outcome, zero `message.send` rows, and no new notification. |
| Changed base revision | The remote `main` moves after the candidate is prepared (before review completes). Policy `max_repairs=0`. | Publish is `conflict` (`target_moved`), the outcome is `exhausted`, and the moved ref is never overwritten. |
| Notification retry | The fake destination answers the first delivery `429`, then `200`. | Each report has one delivery, both are `accepted_by_transport`, and the destination saw 3 calls in total. |

The changed-candidate case (a stale candidate revision) is not reachable from
the pilot. A candidate is immutable at revision 1, and the adapter refuses
any other revision (`candidate_stale`, D7 tests).

## Adapter and driver fixes this test required

These are in scope because the test needs them. Each fixes a real gap found
by running on real adapters:

1. **The Host7 outbox wedged on undeclared events.** The engine refuses any event contract that no installed artifact declares. Accepted `work.ensure` seals `aq.work.changed`, and D7 seals `aq.integration.changed`; no D9 or D11 artifact consumes either. The first quantum after any `work.ensure` failed with `Unknown`. `Driver` now tracks the declared contracts (name and fingerprint) of installed artifacts. On Host7 it retires an undeclared outbox event with zero destinations instead of sending it.
2. **D7 source and review evidence.** See Coding above.
3. **Twelve commands:** `findings.reconcile`, `message.send` and `decision.request` on Host7.

D9 change: `decision.request` is now inside the Host7 grant ceiling, so `CodingPolicy::build()` accepts a human decision. `build_for` with a grant that lacks it still refuses (`NotGranted`); the D9 test was updated to show that.

## Limits

- **PB-04 is not claimed.** aq-server still vendors aq-playbooks `0173673`, so D10's incremental storage is not vendored.
  - The test observed the cost directly. In a debug build on a loaded host, one 8-transition tick grew from about 1.3 s to more than 5 s within one namespace, which is the driver's owner-call bound (`CALL`). The tick then failed `Unknown`.
  - The test therefore uses `Limits { transitions: 2 }` and a fresh namespace per group.
  - Re-vendoring D10 is a follow-up (below).
- **`decision.request` has no human route yet.** Only the trusted `Service::answer_decision` call answers a decision. Expiry is observed lazily by `operation.get` and by an answer; there is no collector. Cancellation is not implemented: the runner's cancel is `Refused`, as for other host commands.
- **Nothing in production writes `aq:source_receipt`** (or `aq:review_disposition`) on work nodes yet. The task lifecycle must do so before the coding pilot can publish outside this test.
- **The routing constraint for a judged choice is the judgment reference, not the choice text.** The catalog 2.0.0 completion output is a union, and its only common fields are `reference` and `subject`.
- The three extra fakes listed above.
