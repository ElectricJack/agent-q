# AQ22 observation ledger checkpoint

This checkpoint adds a durable PostgreSQL adapter for the pure accounting reducer and the exact CON03 batch/receipt transport. It is partial AQ22 implementation. Migration014 is a draft exercised explicitly by integration tests until ordered migrations012/013 are integrated. The worker route is constructed explicitly in tests; production router mounting, source catalog admission, inspection CLI, retained raw artifacts, baseline admission and budget/cost projections remain pending.

The daemon owns source admission. `register_source` requires an actual sealed profiled grant, derives the stable task lineage, and checks the selected provider/account. Its source policy, stable account namespace, parser priorities and qualification evidence must come from a trusted central catalog producer. It is not exposed as a worker registration API. Exact existing source admission can replay after cancellation; a new source cannot. Tests use explicit synthetic policies and actual profiled authority fixtures, not released harness qualification.

An observation batch is accepted only for its authenticated node and exact retained source/generation/native key/parser/session binding. Historical reports from an admitted source do not renew execution or release a task claim. Node revocation is checked again under lock, including for retries. The coordinator keeps a node-wide sequence across source/boot history. A gap in the transport sequence or a changed message identity is refused. The exact receipt, immutable source observations, accounting decisions, canonical fact replacements, lineage aggregate and ACK watermark commit together. Failure at receipt persistence rolls all changes back. Retries return the original receipt without charging again.

Lock order is node, sorted attempts, node transport ledger, sorted call identities, then sorted lineage aggregates. Separate observation SQL connections (four, with bounded acquire/statement/lock waits) and request admission (two concurrent, eight-second handler deadline) isolate this path from the control connection pool. The transaction still takes shared authority row locks: this checkpoint does not claim a measured control-latency or hundred-agent throughput budget. The compact AQ08 authority path and end-to-end performance qualification remain necessary.

Limits are finite: at most256 admitted sources,65,536 retained events and128 MiB conservatively charged logical metadata per node. Sources, events, packet receipts and historical facts are immutable under SQL triggers; canonical heads and constant-size lineage aggregates are mutable projections. Quota exhaustion refuses atomically. These are application accounting bounds, not a claim about PostgreSQL physical storage overhead. There is no automatic deletion, quota reuse or namespace reset; retention/erasure must preserve replay fences before runtime adoption. Text/tool artifacts remain references and are not represented as uploaded/retained transcript bytes.

Corrections replace canonical contributions rather than adding a second bill. Worker cost claims are not trusted prices. Unavailable cumulative baselines and account/category conflicts are retained as explicit unresolved accounting, never manufactured zero usage. Baseline and rate-card owner producers are still pending, so this adapter does not yet produce cumulative totals or cost estimates. Arrival time is sampled centrally after locks and stored separately from untrusted worker observation time.

The accounting component now keeps partial/unqualified canonical calls distinct from known category subtotals. A worker `ReportedComplete` claim cannot produce complete accounting without central selected-version parser qualification evidence. Exact corrections can replace partial facts with qualified complete facts without changing call count. Pinned rate-card estimates stay unknown for partial/unqualified sources while retaining an explicitly labelled non-invoice estimate for represented quantities. Existing native WRK15 format inventory remains unqualified; synthetic qualification artifacts in tests do not change that inventory.

Validation:20 pure accounting tests; seven real PostgreSQL/API tests covering exact retries/corrections, concurrent retries, atomic batch refusal, sequence gaps, late reporting, cancellation, revoked credentials, account/baseline uncertainty, quota rollback, injected receipt failure, immutable history, node-only bearer authentication, foreign packet scope and body bounds. Strict all-target/all-feature clippy and workspace formatting passed. No live provider, human notification or production service was used. Clean retained evidence is recorded separately against the source checkpoint.
