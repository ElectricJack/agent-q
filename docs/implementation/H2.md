## What each goal maps to

- **Source registration from the production attempt path.**
  - `observations::catalog` (`src/observations/catalog.rs`) derives the
    `OwnerSource` from the trusted `IntelligenceConfig.accounting` catalog,
    keyed by the selected (provider, harness). The worker supplies none of it:
    - the policy reference, layout, parsers and priority come from the catalog;
    - the account scope and call namespace are digests of (provider,
      account reference), so retries and wakes deduplicate replayed history;
    - the source id is derived deterministically from (attempt, generation,
      catalog entry);
    - the billing basis comes from the credential kind (`api_key` gives
      `TokenRates`; `subscription_login` gives `SubscriptionAllocation`).
  - Callers:
    - `profiled_execution::started::record`, after commit, best effort;
    - the batch route `POST /v1/worker/observations/batch`, for each attempt
      in the batch, before ingest. Each call checks that the attempt's session
      node is the authenticated node.
  - Registration goes through the existing `observations::register_source`,
    which is idempotent and digest-checked.
- **H1 batches reach the ledger.** The batch route path is
  `ingest_authenticated`, unchanged apart from rate-card pinning.
- **Versioned rate card.** In `aq_accounting::pricing`:
  - `RateCardRevision{revision, corrects, card}`;
  - `RateCardBook`, a chain per (provider, model) that starts at 1. Each
    revision corrects its predecessor with the same layout and currency.
  - Ingest pins `book.current(provider, model)` only for `TokenRates` sources.
  - Reads price each fact with the newest revision in its pinned card's
    family (`effective`). A correction therefore re-prices a call and never
    adds a second charge for it. Covered by
    `rate_card_corrections_are_revisions_that_reprice_once`.
- **Cost kinds.** `pricing::summarize` emits:
  - `ProviderReported`, one component per currency, with a reported zero kept;
  - `NonInvoiceEstimate{TokenRates}`, one component per (card, currency);
  - `Unknown{NotApplicable}` for subscription or local billing, with the basis
    named in the completeness reason;
  - `Unknown{NotReported | Incomplete}` otherwise.

  A reported zero stays distinct from unknown
  (`reported_zero_is_distinct_from_unknown`).
- **Usage route.** `GET /api/observations/sessions/{attempt}/usage`
  (`inspection::usage`) summarizes the call heads that the attempt owns.
  Completeness is `CompleteForPolicy` only when every call is priced and the
  projection has no incomplete or unresolved calls.
- **Lineage budget.** `observations::budget::lineage` sums every canonical head
  in the task lineage, across attempts. Ownership is immutable and replays
  deduplicate by call key, so retries never reset or recount.
  - A project cost limit without `require_hard_cost_enforcement` is a soft
    ceiling. Reaching it inserts one immutable `accounting_policy_events` row
    (migration 0054, idempotent on (lineage, ceiling, threshold, currency)).
  - The resolver fills `BudgetSnapshot.{spent_microunits, currency, accounting, accounting_source}`.
    `hard_budget_provider` stays `None`, so
    `hard_cost_enforcement_unqualified` still refuses a hard requirement
    (0004 §2.2).

## Verification

All runs use `DATABASE_URL=postgres://postgres:test@127.0.0.1:55432/postgres`.
The shared test Postgres runs out of lock memory (`53200 out of shared memory`)
when many store fixtures start at once, so the DB tests ran with
`--test-threads=1` or `2`.

- `cargo test --locked -p aq-accounting`: 22 passed, including
  `rate_card_corrections_are_revisions_that_reprice_once` and
  `reported_zero_is_distinct_from_unknown`.
- `cargo test --locked -p aq-server --test observations`: 12 of 13 pass,
  including both acceptance tests. The one failure,
  `worker_route_requires_node_credentials_and_rejects_wrong_packet_scope`,
  predates H2. Its cookie-only request gets 403 from
  `delegated_permits::runtime::authenticate_runner` (`refused()` when the
  Bearer header is missing), but the test expects 401. That code and test are
  byte-identical on origin/main c60641af, and H2 does not touch them. Filed as
  clear-crest-61.2.1.
- `cargo test --locked -p aq-server --test dashboard_usage`: 2 passed. An empty
  usage read still reports `Unknown{NotReported}`.
- `cargo test --locked -p aq-server --test intelligence`: 6 passed (the resolver
  now reads the lineage budget).
- `cargo test --locked -p aq-server --test image_labels` (2 passed) and
  `--test store` (14 passed) confirm the format-54 bump.
- `cargo clippy --locked -p aq-accounting -p aq-server --tests`: no warnings.
- `cargo fmt`: clean.
