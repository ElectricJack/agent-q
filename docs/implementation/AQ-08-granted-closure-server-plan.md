# Granted closure owner and ordered schema proposal

Status: plan for review, not an implementation. Public contract candidate source `f5f61b3` and evidence `167f17c` are frozen independently. This owner must build on the qualified fresh-Graph initial-grant fix and the separately frozen Renew/Reconcile owners. Root must confirm the next migration reservation; `0028_profiled_launch_closure.sql` is proposed only if the registered head remains 27. Migration27 and admission0.1.7 bytes remain untouched.

## State and authority boundary

A successful operation means **launch closed, awaiting independent settlement**. It does not mean NeverGranted, centrally Started, task success, released capacity, a clean workspace or completed effects. An issued grant remains in history with its immutable hard deadline and any renewals. The original task claim remains held. Suppression and actual host ECHILD provenance remain distinct in the stored request.

Use an immutable closure row as the authoritative terminal launch fence, independent of the physical-phase journal and source/effect/release owners. On first admission also mark the compact authority revoked/cancelling, revoke further agent credential issuance and admitted material retrieval, and retain grant/owner identities. Keep the existing stop projection conservative; do not synthesize post-Started Stopped or NotStarted records. Existing Reconcile can conservatively show StopRequired; the new receipt is the explicit historical closure acknowledgment. A later settled/released view needs its own qualified owner and must not rewrite this receipt.

No production capability is enabled by applying empty schema. A historical proof-verifier policy must be explicitly installed by trusted startup configuration before the route admits a new closure. Absence or unsupported proof profile refuses and keeps the claim. First component tests may install an explicit synthetic policy; that does not qualify a live worker proof producer.

## Exact original provenance

Current `registration::admitted_runtime_locked` reads only `execution_nodes.state.native`. Its boot is overwritten by a later registration, so it is not a permanent historical lookup. Register receipts alone lack the original qualification and cannot reconstruct it.

Propose an append-only `profiled_native_registration_history` keyed by `(node_id,boot_id)`, containing bounded canonical NativeRegistration bytes, their raw digest and actual runtime/qualification references. New native registration inserts this snapshot in its existing node-locked transaction. It may never replace a different snapshot under the same key.

Do not blindly backfill arbitrary JSON during migration. Existing held attempts may capture the actual current NativeRegistration under the enrolled-node lock only when its original boot matches and the existing claim guard has prevented replacement. Validate its original semantic digest, Register, qualification and revision, then persist the canonical snapshot. If the boot has already been replaced and there is no independently retained original snapshot, refuse first admission; never borrow the new runtime/qualification or infer it from an active allowlist. Exact replay later uses the closure's captured original context rather than requiring the old boot still be current.

A separate bounded historical verifier policy maps exact original runtime/qualification to supported closure evidence profiles and pinned verifier/worker qualifications. It is independent of launch eligibility: retiring an active launch allowlist does not retire this cleanup-verification policy. Explicitly unsupported/unknown verifier history remains held. The policy is not inferred from serde validity, a material file or a worker capability string. Store the verifier pin used for an admitted closure so later receipt readback does not depend on active eligibility.

## Proposed records and bounds

`profiled_launch_closures` has one row per exact attempt and a unique `(node_id,operation_id)`. It retains original binding/grant/reservation/logical guardian/launch IDs, original initial-Prepare operation, captured original runtime/qualification/registration context, verified evidence kind/profile, canonical request and immutable receipt bytes, domain request digest, raw byte digests, terminal journal revision/digest and recorded authority revision/time. Foreign keys bind existing attempt and initial receipt owners. Binding/owner data must match owning rows; caller-nominated context is never stored as trusted facts.

Use explicit bytea bounds: request ≤32 KiB, stored owner context ≤64 KiB and receipt ≤16 KiB, with total logical payload ≤112 KiB per row. Logical charging is exactly the sum of these stored byte lengths, both for incoming and existing rows. Proposed retained-history caps are 4096 rows/64 MiB globally and 256 rows/4 MiB per node, consistent with this finite native component's existing history envelope. Row count separately bounds fixed SQL/index metadata; these are logical payload limits, not physical PostgreSQL/RSS ceilings. Confirm these caps at review before implementation. A shared closure quota lock plus SERIALIZABLE predicates prevents concurrent overshoot. No unresolved row is evicted to admit new work, and no long-lived capacity claim follows from this finite quota.

The history table has a separately explicit finite count/byte cap and validates bounded metadata before loading. Reads use node/attempt/operation keys and at most two candidates when ambiguity is possible. No global JSON body fetch, unbounded recovery scan, external cache or mutable second authority is introduced. Closure rows and registration history reject UPDATE/DELETE through owning SQL guards. Later retention of settled audit history is a separate policy, not part of launch closure.

## Transaction and replay

The service accepts only the new bounded `granted_closure::Request` on an outbound machine route such as POST `/v1/worker/profiled/launch-closure`, using the existing opaque AuthenticatedNode/current credential recheck and reserved control admission/pool. There is no inbound worker listener, SSH path or arbitrary filesystem argument. It returns `granted_closure::Receipt`, not a fresh grant or StopEvidence compatibility envelope.

One bounded SERIALIZABLE transaction is sufficient because remote kernel/fsync proof validation belongs to the qualified worker producer, not an RPC inside this transaction. Lock current enrolled node/credential, then exact original attempt and hot authority, then original initial grant/Prepared owner records, historical registration/verifier facts, terminal closure row and mutable credential/material owners in deterministic ID order. Acquire the bounded closure quota lock only after these predicates. No provider, Graph, Git or private file I/O occurs under these locks. Proposed limits match the control lane: finite total request deadline plus explicit SQL lock/statement timeouts; no automatic mutation retry with replacement IDs.

Before a first admission, require actual issued native grant history, the original full owner/binding and held claim; reject NeverGranted, absent original data, contradictory physical state or any actually admitted Started receipt. A hot Running projection without its actual Started record is inconsistent, not proof of no Started. Historical grant/material expiry, cancellation and active qualification retirement do not themselves prevent valid cleanup. Current enrolled-node authentication remains mandatory.

Validate the public request against trusted original GrantedContext. Also require terminal journal revision to exceed the latest acknowledged worker counter. Renew 0.1.7 carries only a journal revision: its canonical request digest is **not** a remote journal digest. Consume the renewal owner's bounded `latest_renewal_revision_locked` accessor, keep that digest unknown, and compare actual digests only for retained physical checkpoints such as Prepared. Suppression's previous snapshot must include the latest acknowledged counter; driver intent may precede a later pre-Started renewal. Qualified durable worker history supplies the later chain.

Atomically insert the closure/fence, revoke further launch/renewal/credential/retrieval authority and persist the immutable receipt/context. Any receipt, revocation, quota or journal association failure rolls everything back. Exact same operation/canonical request returns the original receipt without revision/expiry changes. A changed same-ID request, different replacement operation for an already closed attempt, conflicting variant or ambiguous original history refuses. Receipt readback uses current node authorization plus captured immutable original context, allowing the original boot's historical acknowledgment after a later legitimate boot; it grants no current authority.

## Common terminal fence seam

After the ordered migration exists, define a strict `ensure_launch_open_locked(tx, exact_binding)` used by initial-grant mutation/fresh delivery, Started and Renew mutation/fresh replay. It queries the authoritative closure owner while their common node→attempt/hot locks are held. There is no table-absent permissive fallback. Reconcile/history reads may report conservative terminal state, but never derive permission from a receipt.

If Started wins the lock order, no no-Started closure is admitted and the existing post-Started stop owner applies. If closure wins, neither Started nor a fresh Renew delivery can be admitted afterward, including an old renewal operation replay. If Renew wins first, closure must account for its latest acknowledged counter while preserving the actual immutable grant identity and hard deadline. Add SQL guards against a closure-bearing hot row becoming granted/unrevoked or credential issuance resuming, so future owner mistakes cannot bypass the terminal fence. Keep the physical phase 18 journal distinct; a renewal counter is not a new physical proof phase.

## Worker and settlement gates

Suppression requires a qualified opaque journal method that verifies complete original history, no launch intent, original/current kernel provenance and terminal fsync, then permanently forbids another launch intent. A pre-hook durable driver intent must precede all host/adapter calls capable of effects; the host's later callback alone does not establish this. Missing/corrupt/unsupported history stays unknown.

The physical variant must come from actual opaque host StoppedProof after ECHILD, linked to the exact original intent/configuration/physical guardian, without a synthetic Running record. Missing pane/root status and zero reap count remain legitimate pre-start shapes. A kernel reboot, vanished PID/socket or absent central Started is not substitute evidence. Actual model/tool writer ownership must be qualified; arbitrary adapter side effects outside the guardian are not covered by ECHILD. Neither variant releases local material/workspace resources until the returned central receipt and separately qualified source/effect settlement/release are durable.

## Qualification before activation

Require fresh database and populated 27 upgrade/rollback/refusal tests for the ordered schema, with schema installation alone admitting no runtime owner. Actual PostgreSQL/HTTP cases must cover both evidence variants under explicitly synthetic proof profiles, no-Started/Started races in both orders, renewal races/current counters without invented digests, current credential rotation/revocation after waits, expiry/retired launch eligibility, original versus replaced boot provenance, ambiguous/missing original history, same-ID conflicts, lost reply/restart replay and quota concurrency/rollback. Assert no task release, no synthetic Started/Stopped/NeverGranted and no authority reactivation.

Then qualify actual opaque suppression and actual pre-start host stop production on the worker, including interrupted fsync, launch-intent crash windows, lost replies and restart. Only after that owner/protocol integration can a runtime profile advertise this cleanup capability. Resource/effect settlement and full native restart/product acceptance remain separate gates. No server implementation begins before this plan is reviewed.
