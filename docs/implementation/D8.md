## Implementation

The new `Monitoring6` namespace profile extends the pinned D4 host catalog with the existing confirmed graph/settlement events. Existing profiles 1–5 and vendored contract bytes are preserved. Operator configuration selects `monitoring_v6`; production startup binds the existing agent-access graph gateway. There is no new worker registration or activation endpoint.

`findings.reconcile` uses the existing grant, exact-contract, deadline, retained-effect and namespace-budget framework. AQ owns partitioned episodes, their monotonic revisions, suppression and reminder timestamps, immutable observation/evaluation references, and frozen notification requests. Every successful positive observation advances its episode revision; unchanged evidence suppresses another notification until the reminder interval elapses. Zero disables reminders. Reopening, changed evidence and clearing produce notification intents.

The trusted host calls `Driver::start_health_scan` (or the owner-proven Service equivalent) **before** its diagnostic scan. That call fixes all episode revisions and a maximum 60-second expiry. After verifying coverage, the host calls `complete_health_scan` with the evaluation reference and completeness. Replays cannot replace the original baseline, extend expiry, change evaluation or upgrade partial coverage. These are in-process host APIs, not playbook commands or worker HTTP endpoints. A playbook cannot attest completeness.

Partial evaluations may report positive findings. Missing keys clear only after host-attested complete coverage and only if current revisions still match the original baseline. A concurrent change conflicts the entire complete reconciliation. Supplying a newer revision with old observation/absence evidence cannot repair it. Observation-level receipts preserve the original result across different intent IDs; changed content conflicts. Episode mutations, notification intents, observation receipts and the effect receipt share the AQ transaction. Capacity failure rolls all of them back.

The `health_observations` view of `context.read` returns the pre-scan revisions as JSON `{finding_key: revision}` in the pinned `snapshot` string and an observation identity in `reference`. The trusted evaluator uses that reference to attest its evaluation. Unsupported pages or snapshots over the 4096-byte wire bound report `incomplete`; mismatched requested snapshots report `expired`. Historical profile 5 retains its incomplete health view.

Notification draining calls the existing notifications owner's `enqueue` after the AQ commit. The immutable request fixes both operation and logical message IDs from namespace/generation/partition/key/revision. A lost local acknowledgement replays the same request and creates one logical message. Submission follows durable episode transaction order, so a retained clear cannot overtake its opening notification. Capacity and temporarily unavailable notification scopes retain the frozen intent for retry. Routing, visibility, transport, delivery and human acknowledgement remain owned by notifications. Intent submission does not claim delivery.

## Calendars and ingress

`Driver::put_schedule` accepts a host-owned `DailySchedule`: UUID, IANA timezone, local hour/minute, start date and `Misfire`. Registration uses expected-revision CAS and preserves each definition revision. PostgreSQL timezone rules shift nonexistent DST times forward and choose standard time in an overlap. The occurrence identity is namespace/generation/schedule/revision/local date. Its `aq.signal.reported` reference is `aq.schedule/<schedule>/<revision>/<date>`.

Cursor advances and sealed outgoing events commit together before engine delivery. Skip discards missed dates and emits today's occurrence only within 60 seconds of its due time; coalesce emits the latest due date once; catch-up emits oldest dates in batches of 1–32. A bounded due-only schedule page prevents an idle timezone from starving another due schedule. Clock rollback cannot move a cursor backward. A new schedule revision has a separate occurrence identity. Collection starts after an installed artifact declares the exact occurrence contract.

Confirmed D3 graph operations and task settlements use the existing sealed outbox and engine `Event`/`Fanout` receipts. Outbox identity now includes producer as well as event UUID; acknowledgements select the exact producer using the engine receipt key. The pinned engine retains destination activation/rule snapshots, per-destination root deduplication, content conflicts and catalog revisions for no-match dispositions. The existing `AdmitOnce` and HTTP admission path are preserved.

Namespace budgets remain 4096 manual admissions, 8192 effects, 16384 outbox records and 64 MiB retained accounting. There are at most 128 schedules and 100 episode keys per partition; identifiers are bounded to 512 UTF-8 bytes and evidence references to 4096 bytes. The engine's configured bounds also apply. Atomic quota refusals map to typed `Overloaded`; HTTP returns 429 with `retryable: true`. Automatic drive retains pending work when capacity refuses admission and still drains previously retained events, cancellations and run ticks before reporting retryable pressure. Notification enqueue refusal also leaves independent work progressing. Nothing advances a schedule cursor on refusal.

## Review and fixes

One fresh `gpt-6-astra` reviewer inspected the integrated implementation against the plan and specification. The review found no critical issue, two important issues and one minor issue. Both important findings were fixed: collection/admission backpressure no longer prevents independent event draining and run ticks, and human-decision copying includes producer identity when looking up a retained event. The minor finding was also fixed by draining notification intents by a durable insertion sequence rather than UUID order.

Each issue had a failing regression before its production fix (`review-red.log`: 6 passed, 2 failed; `review-decision-red.log`: producer collision failed with `Conflict`). Additional coverage acknowledges two valid protected events sharing a UUID independently. The corrected target passes all 9 tests, and the decision collision regression passes against the real protected driver. Final results include these corrections. The task is not marked for an additional AQ adversarial review; no second fresh review is claimed.

## Limits and delivery

Snapshot pagination beyond the bounded first page is explicitly incomplete. Tests use PostgreSQL and the actual pinned engine/protected backend; diagnostic graph mutations are not exercised against a live graph service. The existing activation browser probe remains ignored because it requires an explicit compiled dashboard and browser provider; no browser/UI changes are claimed.
