# Granted closure contract candidate

This is an additive public-contract slice in candidate aq-admission 0.1.8. Version 0.1.7 archives, existing wire structs, schemas and fixtures remain unchanged. No runtime capability, SQL migration, route, worker recovery or release owner is implemented by this slice.

The proposed `granted_closure` module bounds requests and receipts to 32 KiB. A strict Request binds one operation, full original LaunchBinding, grant, reservation/logical guardian/launch, installed runtime and historical qualification, and terminal worker journal checkpoint. Its evidence is one tagged variant:

- `Suppressed`: a durable SuppressionRecord with the same binding/owner/operation, suppression ID, original and recording kernel boots, prior journal checkpoint and terminal revision, plus its domain-separated canonical digest. It describes a qualified terminal local-journal transition before any launch intent, not an absence inferred from central Started. Original logical boot remains in SessionIdentity. The original kernel boot is worker-journal provenance, not a fact reconstructed from machine registration.
- `HostStopped`: a durable driver launch-intent checkpoint and the actual serialized opaque host StoppedProof, plus its digest. The new observation mirrors the host shape with optional pane/root status and a zero-allowed reaped count; phase must be stopped and kernel ECHILD must be true. Guardian intent/configuration, physical nonce, kernel boot, PID namespace, process birth identities and permit sequence/deadline remain exact. Driver intent must precede all host/adapter startup hooks that can create effects.

A caller-supplied **trusted internal**, non-Serde GrantedContext contains the actual immutable GrantedLaunch, runtime/qualification and centrally recorded Prepared journal checkpoint. Pure validation checks correlation and journal progression against these facts; it does not establish current machine authentication, retained qualification, absence of central Started or a terminal SQL fence. The runtime owner must obtain those facts under the common node/attempt locks and serialize closure against Started/renewal. No synthetic Accept/Prepare/Started is needed.

A Receipt returns an immutable request digest and recorded authority revision with the sole disposition LaunchClosedAwaitingSettlement. It has no execution clock, success flag, task-release or cleanup permission. Replay is historical and cannot renew execution, restore credentials, reset boot identity or free capacity. Independent source/effect settlement remains mandatory.

The host's valid stopped-with-no-child case is pane None, root status None, reaped count zero. A server that exited before pane creation may produce pane None with a root status and positive count. Previously Running hosts can produce the same complete pane-bearing proof even if central Started was lost. The new DTO must accept these actual shapes without weakening the frozen post-Started type. Missing identity/state or an uncertain guardian supplies no proof. First-profile bounded strings may refuse unsupported host error text; producers may not truncate it and claim an exact opaque proof.

Canonical digests are domain-separated for suppression records, host proofs and closure requests. DTOs deny unknown fields and reject nil IDs, invalid process identities, clock/revision overflow, invalid scopes, false ECHILD and contradictory journal correlations. Validation remains structural; arbitrary JSON cannot become kernel attestation or fsync evidence. The future qualified worker owner must persist the request before sending and the receipt before settlement.

Qualification will retain valid and invalid fixtures, schemas, independent canonical vectors and deterministic drift checks. A standalone extracted candidate package must compile/test/lint offline against exact frozen dependency archives. Actual worker opaque suppression/stop production and SQL admission are separate followups, with granted/no-Started claims held until both qualification and settlement exist.
