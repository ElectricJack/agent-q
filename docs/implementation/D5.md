## Effect discipline

- **Intent first.** Every command first validates the command name, the contract fingerprint, the input schema, the size limit and the payload digest. It then takes the namespace lock, checks the runtime owner and loads the effect row `FOR UPDATE`. The effect is keyed by namespace, `Intent.id`, contract fingerprint, payload digest, grant and revision.
  - An existing row with the same identity returns its retained result.
  - The same `Intent.id` with different bytes (or a different grant or fingerprint) is `Conflict`.
- **Authority.** Authority comes only from the live grant capability set. The grant and the intent deadline are checked on a fresh intent, and expiry is checked again after the lock wait, just before commit.
- **Two-phase external effects.** The `pending` effect row commits first. The graph mutation or B3 cancel then runs with a stable idempotency key or operation id. A finish transaction writes the final status and the sealed `aq.work.changed` outbox entry (`aad("aq.playbooks.outbox", event_id, digest)`) together. If a crash happens between the phases, the row stays `pending` and `reconcile` reports `Unknown`. Reconcile never re-executes the effect.

## Adapters

- **context.read** returns typed views only: `work`, `project`, `execution_options`, `evidence` and `health_observations`. No SQL or graph query is passed through. A snapshot mismatch gives `expired`.
- **work.ensure** accepts only the manifest kinds. It is idempotent by logical key through `playbook_work_keys` (digest of the namespace and key). The node is created through the graph gateway with a `motivated_by` edge. The outcome `ensured` means only that the node exists, not that the work is complete.
- **work.change** accepts only the closed manifest variants (requirements, priority, dependencies, execution_constraints, hold, release_hold). It uses the graph CAS `expected_version`. A stale version gives `conflict` with the current revision and makes no mutation. It never writes `task_state`, so there is no lifecycle shortcut. Work that the namespace did not ensure is refused.
- **operation.cancel** dispatches by a server-owned handle (`aq.execution.attempt/<id>` or `aq.playbook.work/<id>`), and project ownership is checked first. Native attempts go to B3 `profiled_execution::cancellation::cancel`. B3 dispositions map to outcomes:
  - `Requested` → `accepted`
  - `NeverGranted` → `cancelled`
  - `AlreadyAccepted` → `too_late`
  - `NotFound` / `BadRequest` → `refused`
  - `Conflict` → `indeterminate`
  - Any other B3 error returns `Unknown`, and the effect row stays `pending`.

## Limits (documented, not hidden)

- The adapter tests use an in-memory `WorkGraph` fake with CAS and idempotency replay. `GatewayGraph` is the production port. It reuses the existing settlement request and response validators and is not exercised against a live graph here.
- There is no owned-work completion event (`aq.operation.updated`). `ensured` is reported, and completion tracking belongs to a later deliverable.
- `operation.cancel` on a `aq.playbook.work/` handle that has no profiled attempt is `refused`. No cancel outbox event is emitted.
- `health_observations` always reports `incomplete`.
- `context.read` paging is not implemented: `next_page` is always `null`.
- `work.change` and work-scoped `context.read` apply only to work that this namespace ensured.
- The D4 `replay_cases` cover `message.send` and `decision.request`, which are outside D5. The fixture test checks them at schema level only.
- Out of scope: D6, D7, D8, G2/F2 and B3 internals.
