# Pure central selection v1

This new closed contract belongs to `aq-selection`0.1.4. It neither changes the
existing task selection wire nor grants execution. Input/output schema and actual
compile→select vectors are generated by the explicit opt-in central test; normal
tests compare the packaged frozen copies and never rewrite them.

Use `central::select_central(actual_catalog, &inputs)` and
`verify_central_selection(actual_catalog, &inputs, &outcome)`. `decode` rejects
unknown/duplicate typed fields, invalid integer representations, trailing data
and documents above32MiB; semantic checks happen in selection/reverification.
Outcome encoding is limited to256KiB. The schema's x-required-validation marks
constraints which require actual catalog/43ac rederivation and current owner facts.

Each `Pinned<T>` hashes actual canonical compact recursively sorted UTF-8 JSON
bytes of `value`; its identity is `aq.central-selection.<kind>/<sha256>@1` with
that exact lowercase SHA-256. Fixed kinds are reservation-policy, reservation,
policy, registry and installation. A generated selected artifact uses selection
and carries its actual canonical bytes beside the typed value. These are genuine
data descriptors, not receipts asserting a database retained them or a principal
approved them. Historical inputs and their original expiry are immutable.

Distinct actual domains remain pinned: original schema37 reservation LocalPolicy,
reservation/mail source projection,43ac composition policy and compatibility,
central turn-selection policy, catalog/profile Sources, registry and central
installation incarnation. One policy cannot substitute for another. The pure
adapter authenticates none of them. A future owner must query and fence them.

Central-v1 contains no task/project/workspace IDs or execution generation. Local
credential presence has no worker-preparation field. Worker observations may be
retained as input data but do not influence central availability. The choice
carries exact native model/reasoning, adapter/environment/qualification and
credential/account/endpoint pins. ModelSettings spending_budget is always null.
Unknown cost requires BOTH intelligence AllowBounded and the explicit central
turn flag. Legacy task semantics remain unchanged. Cost/token totals are
unavailable/null; monetary/hard/complete-accounting policy
requirements refuse selection. InitialSelectionOnly is metadata policy, not a
claim that a model was started or runtime retry accounting exists. Original
43ac bundles remain unmodified/unresolved; a selected artifact links to them.

The later authenticated artifact owner and subject-neutral HostPlan/permit/
credential/runtime join have separate implementation/qualification gates. No
production capability, HTTP route, daemon registry or migration is added here.
