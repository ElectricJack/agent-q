# AQ lifecycle API contract 0.1.0

This pure contract package describes future AQ-owned wait registration, continuation acknowledgment, bounded inspection and operator requests. It installs no daemon routes. It consumes the exact normalized `aq-lifecycle-protocol =0.1.0` package, whose worker-owned observation and parking claims remain distinct from authoritative runtime evidence.

Requests seal a stable operation UUID and canonical payload digest. Reusing the UUID with another payload refuses. Each command requires its own versioned capability; graph read permissions and node credentials do not confer these capabilities. CallerContext is a trusted fake input, never a wire credential. A real adapter must authenticate, check current attempt/boot/generation and scope, serialize admission/cancellation, and persist replay records before effects. The fake has finite 1024-operation and 256-wait capacity; it is not a durable store.

Wait predicates are flat Single, All or Any values with at most 32 unique typed members. Each source boundary records its condition digest, source owner, committed revision/replay cursor and subscription receipt. These values describe the required transaction seam; the package cannot implement subscribe-before-reobserve or prove absence of lost wakeups. Self waits on the same task, wait, operation, run or exclusively own mailbox sender refuse. Any chooses the first satisfied member in declaration order. Pending members prevent Any from resolving as failed. A satisfied `TaskRequirement::Settled` condition may reference a failed task: wait resolution is not task success. Manual override preserves the unresolved predicate digest.

Registered age survives exact re-registration. Task outcome, wait resolution, policy choice, reported parking, wake admission and bootstrap acknowledgment have separate types. Checkpoint recording is not stop verification. Suspended execution is neither ordinary success nor ordinary failure. Only an exact fresh admitted successor attachment can accept its continuation acknowledgment; an old generation cannot clear a new bootstrap gate. Operator requests report requested intent, not performed stop/quarantine. Runtime stop verification, disk retention and wake admission remain later implementations.

Inspection pages are bounded at 64 items and 256 KiB; requests are at most64 KiB. Completeness and unavailable-source reasons are explicit. Producer usage counters distinguish unknown from zero and cumulative generations/corrections retain source/parser/digest provenance. Inspection ledger revisions do not implement accounting. A lineage UUID is provenance, not authority to reset a centrally bound original-task budget; estimates are non-invoice values and no wire claim promises absence of double billing.

Notification transport acceptance, human acknowledgment and decision answer are independent. Delivery unknown cannot manufacture receipt, decision or safe retry. Digest inspection names the schedule occurrence, window, timezone and winning logical revision without sending anything. Discord transport, message persistence and scheduling remain later work.

Run `cargo test -p aq-lifecycle-api --offline`, `cargo clippy -p aq-lifecycle-api --all-targets --offline -- -D warnings`, and `cargo run -p aq-lifecycle-api --example export-aq-lifecycle-api --offline -- --check`. The exporter is the sole schema/fixture source; it mirrors packaged artifacts into `protocol/lifecycle-api/v1` when inside the repository. Extracted-package checks need only the pinned public lifecycle and session packages, not either runtime checkout.
